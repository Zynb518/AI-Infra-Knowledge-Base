# AI Infra Knowledge Base

这是一个面向云端 AI Infra 的长期知识库，通过 Obsidian 管理 Markdown 笔记，并使用 Git 进行版本控制。

当前学习主线见：[云端 AI Infra 学习路线（NVIDIA + 昇腾双栈）](<./AI Infra 云端学习路线（NVIDIA + 昇腾双栈）.md>)。

## 目录结构

```text
AI-Infra-Knowledge-Base/
├── AI Infra 云端学习路线（NVIDIA + 昇腾双栈）.md
├── Knowledge/
│   ├── 阶段0-系统与工程基础/
│   ├── 阶段1-模型与推理基础/
│   ├── 阶段2-加速器与性能工程/
│   ├── 阶段3-推理引擎与在线服务/
│   ├── 阶段4-分布式通信与训练系统/
│   ├── 阶段5-Kubernetes与加速器平台/
│   ├── 阶段6-可观测性、可靠性与成本/
│   └── 阶段7-综合能力/
├── Labs/
├── Projects/
└── Sources/
```

## 目录说明

### Knowledge

按照学习路线的阶段保存整理后的知识。每个阶段下的子知识库范围按实际需要决定，不强制使用统一粒度。

例如，`C++`、`Linux`、`CUDA` 或 `vLLM` 都可以独立成为一个子知识库。通用原理尽量只维护一份，通过 Obsidian 内部链接关联到 NVIDIA、昇腾及相关实验笔记。

### Labs

保存针对单一问题开展的实验，包括代码、配置、环境信息、测试数据和结论。目录可以按照实验主题自由组织，不要求与 `Knowledge` 的阶段结构保持一致。

### Projects

第一层目录只表示项目名称，例如：

```text
Projects/
├── mini-transformer/
├── vllm-benchmark/
└── multi-accelerator-platform/
```

各项目内部的目录、语言和工程结构由项目自身决定，本知识库不作统一限制。

### Sources

保存论文、书籍、课程、文章、官方文档等外部资料的链接与阅读笔记。大型 PDF、数据集和二进制文件不建议直接提交到普通 Git 历史中。

## 内容组织原则

- 学习路线描述学习顺序、阶段目标和验收标准。
- `Knowledge` 保存经过整理、可以长期复用的知识。
- `Labs` 保存实验过程与证据。
- `Projects` 保存完整的工程实践。
- `Sources` 保存外部资料及其阅读记录。
- 一篇笔记可以通过 Obsidian 内部链接关联多个知识主题，无需为了分类而复制内容。

## 命名约定

- 目录和笔记可以使用中文；Obsidian、Git、GitHub、Windows、macOS 和 Linux 均支持 UTF-8 中文路径。
- 避免在名称中使用 `/`、`\\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等跨平台不兼容字符。
- 文件名应简短、清晰，并尽量在整个知识库内保持唯一。
- 技术名称保留常用英文写法，例如 `C++`、`CUDA`、`KV Cache` 和 `vLLM`。
- 在命令行和脚本中引用包含中文或空格的路径时，应使用引号包裹完整路径。

## 使用方式

1. 根据学习路线确定当前阶段。
2. 将整理后的概念写入对应的 `Knowledge` 阶段目录。
3. 将验证过程记录在 `Labs`，并链接到相关知识笔记。
4. 将完整成果放入 `Projects`，项目内部自行组织。
5. 将参考资料和阅读记录放入 `Sources`。
