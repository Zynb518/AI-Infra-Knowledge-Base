# 函数、局部变量与脚本组织

## 引入

脚本变长后，如果所有命令都直接写在顶层，重复逻辑会越来越多，修改和排错都会变得困难。

函数可以把一组相关命令封装成一个可重复调用的单元。本课学习如何定义函数、给函数传参数、使用局部变量，并用 main 函数组织脚本的入口。

## 核心内容

### 定义和调用函数

Bash 函数的常见写法是：

~~~bash
print_service() {
  printf 'service: %s\n' "$1"
}

print_service api
print_service worker
~~~

函数定义中的命令不会在定义时立即执行，只有调用函数时才会执行函数体。

调用函数时直接写函数名和参数，不要写成 print_service()。括号用于定义函数，不用于调用函数。

### 函数有自己的位置参数

函数调用时传入的参数，会成为函数内部的 $1、$2 和 $@：

~~~bash
print_pair() {
  printf 'first: %s\n' "$1"
  printf 'second: %s\n' "$2"
}

print_pair api 'test environment'
~~~

函数内部的 $1 是函数收到的第一个参数，不是脚本本身的第一个参数。脚本参数和函数参数分别属于各自的调用层级。

如果函数需要转发收到的全部参数，要使用双引号保护的 "$@"：

~~~bash
print_all() {
  for item in "$@"; do
    printf 'item: %s\n' "$item"
  done
}

print_all api 'test environment' database
~~~

### 使用 local 限制变量作用范围

函数中的变量默认可能影响函数外部的同名变量。使用 local 可以让变量只在当前函数中有效：

~~~bash
show_service() {
  local service="$1"
  printf 'inside: %s\n' "$service"
}

show_service api
~~~

local 只能在函数内部使用。函数中的临时变量、循环变量和中间结果，通常都应该使用 local，避免意外修改脚本其他位置使用的变量。

函数参数本身不需要使用 local 声明；\$1、\$2 和 "\$@" 会由 Bash 根据函数调用自动提供。

### 函数可以返回退出状态

函数和普通命令一样，会有退出状态。可以使用 return 明确返回状态：

~~~bash
is_ready() {
  if [ "$1" = 'ready' ]; then
    return 0
  fi
  return 1
}

if is_ready ready; then
  printf 'service is ready\n'
fi
~~~

return 0 表示函数成功，return 非 0 表示函数失败。函数的返回值是退出状态，不是任意文字。

如果没有写 return，函数通常使用最后一条命令的退出状态作为函数退出状态：

~~~bash
print_status() {
  printf 'status checked\n'
}

print_status
printf 'function status: %s\n' "$?"
~~~

### 用标准输出返回文字结果

如果函数需要产生文字结果，可以让函数使用 printf 输出，再用命令替换取得：

~~~bash
get_service_name() {
  printf 'api\n'
}

service=$(get_service_name)
status=$?
printf 'service: %s\n' "$service"
printf 'function status: %s\n' "$status"
~~~

这里要区分两类结果：

- printf 输出的文字可以被终端看到，也可以被命令替换保存。
- return 提供退出状态，用于判断成功或失败。

### 使用 main 组织脚本入口

较大的脚本可以把主要流程放进 main 函数，把具体动作拆成其他函数：

~~~bash
print_service() {
  local service="$1"
  printf 'checking: %s\n' "$service"
}

main() {
  for service in "$@"; do
    print_service "$service"
  done
}

main "$@"
~~~

这样做有几个好处：

- 函数定义集中在脚本前面，结构清楚。
- main 函数表达脚本的主要流程。
- 最后一行 main "$@" 明确表示从脚本入口开始执行。
- 每个函数可以单独理解和测试。

### 函数组织时的注意事项

- 函数定义和函数调用要区分开。
- 函数参数使用 "$1"、"$2" 或 "$@" 时要加双引号。
- 函数内部的临时变量优先使用 local。
- 文字结果通过标准输出传递，成功或失败通过退出状态传递。
- 函数定义应放在调用之前，便于 Bash 执行时找到函数。

## 示例：组织一个服务检查脚本

下面的脚本把“检查单个服务”和“批量处理服务”分成两个函数：

~~~bash
check_service() {
  local service="$1"
  if [ "$service" = 'api' ]; then
    printf 'known service: %s\n' "$service"
    return 0
  fi
  printf 'unknown service: %s\n' "$service"
  return 1
}

main() {
  for service in "$@"; do
    check_service "$service"
  done
}

main "$@"
~~~

main 负责遍历输入，check_service 负责判断单个服务。以后修改判断逻辑时，只需要修改 check_service。

## 小结（掌握范围）

本课必须掌握：

- 会使用 name() { ... } 定义函数，并直接使用函数名调用。
- 知道函数调用时使用的参数会成为函数内部的 \$1、\$2 和 "\$@"。
- 会使用 local 声明函数内部的临时变量。
- 会使用 return 0 或非 0 返回函数退出状态。
- 能区分函数的标准输出和函数退出状态。
- 会使用命令替换获取函数输出。
- 能使用 main 函数组织脚本的主要流程，并用 main "$@" 传递脚本参数。
- 能把重复逻辑拆成独立函数，减少脚本中的重复代码。

## 课后小实操

### 实操一

创建一个服务报告脚本，使用函数封装单个服务的输出，再由 main 函数批量处理命令行参数。

**操作步骤**

创建 /tmp/bash-course/service-report.sh，并完成以下要求：

- 定义一个接收服务名参数的函数。
- 函数内部使用 local 保存当前服务名。
- 函数输出一行服务信息。
- 定义 main 函数，遍历全部命令行参数并调用前面的函数。
- 使用 main "$@" 启动脚本。
- 参数中包含空格时，仍然要作为一个完整服务名输出。

回到终端执行：

~~~bash
bash /tmp/bash-course/service-report.sh api 'test worker' database
~~~

**代码**

~~~bash
#!/usr/bin/env bash

check_service() {
  local service="$1"
  printf 'service name: %s\n' "$service"
}

main() {
  for service in "$@"; do
    check_service "$service"
  done
}

main "$@"

~~~

**运行结果**

~~~text
❯ bash /tmp/bash-course/service-report.sh api 'test worker' database
service name: api
service name: test worker
service name: database

~~~

### 实操二

创建一个路径检查脚本，用函数返回路径是否存在的状态，并由 main 函数统计普通文件、目录和不存在路径的数量。

**操作步骤**

创建 /tmp/bash-course/path-check.sh，并完成以下要求：

- 定义 check_path 函数，接收一个路径参数。
- 普通文件和目录视为检查成功，不存在的路径视为检查失败。
- 函数需要输出当前路径的分类，并通过 return 返回成功或失败。
- 定义 main 函数，遍历全部命令行参数。
- main 根据 check_path 的退出状态分别统计成功和失败数量。
- 处理路径时必须保留包含空格的参数边界，不要修改任何传入路径。

可以使用已经学过的 local、if、-f、-d、for、"$@"、return 和整数递增。

回到终端执行：

~~~bash
bash /tmp/bash-course/path-check.sh /etc/hosts /tmp '/tmp/bash-course/not found'
~~~

**代码**

~~~bash
#!/usr/bin/env bash

check_path() {
  local path="$1"
  if [ -d "$path" ]; then
    printf 'directory: %s\n' "$path"
    return 0
  elif [ -f "$path" ]; then
    printf 'file: %s\n' "$path"
    return 0
  else
    printf 'missing: %s\n' "$path"
    return 1
  fi
}

main() {
  local success=0
  local fail=0
  for path in "$@"; do
    if check_path "$path"; then
      success=$((success+1))
    else
      fail=$((fail+1))
    fi
  done

  printf 'success: %s, fail: %s \n' "$success" "$fail"
}

main "$@"

~~~

**运行结果**

~~~text
main "$@"
~~~
