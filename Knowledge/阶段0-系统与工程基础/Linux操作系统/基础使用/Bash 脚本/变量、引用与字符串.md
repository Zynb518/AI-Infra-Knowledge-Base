# 变量、引用与字符串

## 引入

上一课的脚本只能重复执行固定的命令。实际工作中，服务名、目录路径、环境名称和文件名经常会变化。如果把这些内容直接写死在每条命令里，修改起来容易遗漏。

Bash 变量可以先保存一个值，再在后面的命令中重复使用。本课重点解决三个问题：

- 如何定义和使用 Bash 变量？
- 单引号和双引号有什么区别？
- 为什么使用变量时通常要加双引号？

## 核心内容

### 定义和使用变量

定义变量时，等号两边不能有空格：

~~~bash
service='api'
port=8080

printf 'service=%s\n' "$service"
printf 'port=%s\n' "$port"
~~~

变量名通常由字母、数字和下划线组成，不能以数字开头，并且区分大小写。

下面的写法是错误的：

~~~bash
service = 'api'
~~~

Bash 会把它理解成要执行一个名为 service 的命令，因为赋值语句中的等号不能被空格分开。

使用变量时，在变量名前加美元符号：

~~~bash
name='worker'
printf 'name: %s\n' "$name"
~~~

也可以使用更清晰的边界写法：${name}。当变量后面紧接着字母、数字或下划线时，推荐使用大括号：

~~~bash
prefix='service'
printf '%s\n' "${prefix}_status"
~~~

如果写成 $prefix_status，Bash 会把 prefix_status 当成完整的变量名，而不是把变量 prefix 和字符串 _status 拼接起来。

### 单引号和双引号

单引号中的内容会按字面保留，变量不会展开：

~~~bash
service='api'
printf 'single quotes: $service\n'
~~~

输出中的 $service 仍然是普通文字。

双引号中的变量会展开：

~~~bash
printf "double quotes: $service\n"
~~~

输出中的 $service 会被替换为变量的值。实际脚本中，推荐使用更明确的格式化写法：

~~~bash
printf 'service: %s\n' "$service"
~~~

这里的 %s 是输出位置，后面的 "$service" 是传给它的值。这样可以把格式和数据分开，阅读和修改都更清楚。

### 为什么变量通常要加双引号

假设变量的值包含空格：

~~~bash
message='api request failed'
~~~

加双引号时，整个变量值会作为一个参数：

~~~bash
printf '<%s>\n' "$message"
~~~

输出一行：

~~~text
<api request failed>
~~~

不加双引号时：

~~~bash
printf '<%s>\n' $message
~~~

Bash 可能会先按照空格拆分变量值，再把拆分后的多个部分传给命令，结果类似：

~~~text
<api>
<request>
<failed>
~~~

不加双引号还可能触发路径名展开。例如变量值中包含星号时，Bash 可能把它展开成当前目录中的多个文件名。

因此，使用变量时应形成一个习惯：

~~~bash
printf '%s\n' "$variable"
command "$path"
~~~

除非你明确希望 Bash 对内容进行拆分或路径名展开，否则都给变量加双引号。

### 用变量拼接路径和文件名

变量常用于保存目录，再拼接出文件路径：

~~~bash
work_dir='/tmp/bash-course/data files'
file_name="${work_dir}/result.txt"

mkdir -p "$work_dir"
printf 'created by Bash\n' > "$file_name"
~~~

这里有两个需要注意的地方：

- 路径中包含空格，所以使用变量时要加双引号。
- 使用 ${work_dir} 明确变量边界，再拼接 /result.txt。

变量保存的是文字，Bash 不会因为变量名叫 file_name 就自动把它当成文件；真正创建文件的是重定向符号 >。

## 示例：用变量生成一份服务信息

下面的脚本把容易变化的信息集中放在开头，后面的输出命令通过变量读取这些值：

~~~bash
#!/usr/bin/env bash

service='api'
environment='test'
message='request completed'

printf 'service=%s\n' "$service"
printf 'environment=%s\n' "$environment"
printf 'message=%s\n' "$message"
~~~

以后如果服务名或环境发生变化，只需要修改变量赋值处，不必逐行搜索并修改输出命令。

## 小结（掌握范围）

本课必须掌握：

- 会使用 name=value 定义变量，知道等号两边不能有空格。
- 会使用 $name 或 ${name} 展开变量。
- 知道变量名区分大小写，通常由字母、数字和下划线组成，不能以数字开头。
- 知道单引号中的变量不会展开，双引号中的变量会展开。
- 能使用 ${name} 明确变量边界，尤其是在拼接文件名和路径时。
- 使用变量作为命令参数时，默认加双引号，例如 "$path"。
- 知道未加双引号的变量可能因空格被拆分，也可能触发路径名展开。
- 能使用变量保存目录、文件名和其他字符串，并通过命令真正使用这些值。

## 课后小实操

### 实操一

创建一个 Bash 脚本，把服务名和运行环境保存为变量，再使用 printf 输出。修改变量值后重新运行，观察输出如何变化。

**操作步骤**

创建 /tmp/bash-course/variables.sh，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

service='api'
environment='test'

printf 'service=%s\n' "$service"
printf 'environment=%s\n' "$environment"
~~~

回到终端执行：

~~~bash
bash /tmp/bash-course/variables.sh
~~~

然后把脚本中的 service='api' 修改为 service='worker'，再次执行同一条命令。

**运行结果**

~~~text
❯ bash /tmp/bash-course/variables.sh
service=api
environment=test

~~~

### 实操二

创建一个脚本，把包含空格的目录路径保存到变量中，拼接出文件名并创建文件。这个练习用于观察双引号和 ${...} 在路径处理中的作用。

**操作步骤**

创建 /tmp/bash-course/path-variable.sh，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

directory='/tmp/bash-course/data files'
filename="${directory}/result.txt"

mkdir -p "$directory"
printf 'created by Bash\n' > "$filename"
printf 'file: %s\n' "$filename"
file "$filename"
~~~

回到终端执行：

~~~bash
bash /tmp/bash-course/path-variable.sh
~~~

**运行结果**

~~~text
❯ bash /tmp/bash-course/path-variable.sh
file: /tmp/bash-course/data files/result.txt
/tmp/bash-course/data files/result.txt: ASCII text

~~~
