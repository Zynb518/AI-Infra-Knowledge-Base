# 调试、错误处理与安全习惯

## 引入

脚本出错时，屏幕上的一条错误信息通常只说明“结果不对”，不一定能马上说明哪一行、哪个变量或哪个命令出了问题。

一个可以长期使用的脚本，还需要处理几类情况：

- 语法写错，脚本根本无法解析。
- 变量没有设置，导致命令使用了错误的值。
- 管道前面的命令失败，但最后一个命令看起来成功。
- 临时文件没有清理，留下过期数据。
- 输入不符合要求，却继续执行了危险操作。

本课学习 Bash 中基础的检查、追踪、错误返回和清理方法。

## 核心内容

### 使用 bash -n 检查语法

bash -n 只检查脚本语法，不执行脚本中的命令：

~~~bash
bash -n /tmp/bash-course/example.sh
~~~

如果语法正确，通常没有输出；如果语法错误，Bash 会给出行号和错误提示。

bash -n 只能检查语法，不能证明脚本逻辑正确。例如变量名写错、路径不存在等问题，仍然需要实际运行才能发现。

### 使用 bash -x 追踪执行过程

bash -x 会在执行命令前，把展开后的命令打印出来：

~~~bash
bash -x /tmp/bash-course/example.sh
~~~

它可以帮助观察：

- 变量实际展开成了什么。
- 条件分支是否进入了预期路径。
- 循环实际执行了几次。
- 命令收到的参数是否完整。

追踪信息通常也会显示在标准错误中。如果脚本中包含密码、令牌或其他敏感内容，不要把 bash -x 的完整输出公开或长期保存。

### 使用 set -u 发现未设置变量

set -u 会让 Bash 在读取未设置变量时报告错误：

~~~bash
set -u
name='api'
printf '%s\n' "$name"
printf '%s\n' "$missing_name"
~~~

这可以帮助发现变量名拼写错误。对于确实允许为空的变量，可以提供默认值：

~~~bash
printf 'name: %s\n' "${name:-unknown}"
~~~

${name:-unknown} 表示：如果 name 未设置或为空，就使用 unknown。

### 使用 set -e 处理未捕获的失败

set -e 会让脚本在未被处理的命令失败时提前结束：

~~~bash
set -e
printf 'before failure\n'
false
printf 'this line is not reached\n'
~~~

set -e 不是所有错误场景的万能解决方案。放在 if 条件、&& 或 || 中的命令，本来就是被脚本显式判断的失败，行为和普通顶层命令不同。因此，预期可能失败的命令，应该使用条件判断明确处理。

### 使用 pipefail 检查管道中的失败

默认情况下，管道的退出状态通常取最后一个命令的状态：

~~~bash
false | true
printf 'pipeline status: %s\n' "$?"
~~~

最后的 true 成功，整个管道可能看起来也是成功的。

打开 pipefail 后，只要管道中有命令失败，管道就会返回失败状态：

~~~bash
set -o pipefail
false | true
printf 'pipeline status: %s\n' "$?"
~~~

处理重要数据时，pipefail 可以避免忽略管道前面已经发生的错误。

### 用标准错误输出错误信息

错误信息应该写入标准错误，而不是混入正常结果：

~~~bash
if [ "$#" -eq 0 ]; then
  printf 'error: an argument is required\n' >&2
  exit 1
fi
~~~

这里：

- >&2 把 printf 的输出发送到标准错误。
- exit 1 结束脚本，并返回非 0 状态。
- 正常结果仍然可以单独通过标准输出重定向或管道处理。

函数内部如果需要通知调用者失败，可以使用 return；脚本顶层需要结束执行时，可以使用 exit。

### 使用 trap 清理临时文件

如果脚本创建了临时文件，应该在退出时清理。trap 可以把退出动作绑定到清理函数：

~~~bash
temporary_file=$(mktemp)

cleanup() {
  rm -f "$temporary_file"
}

trap cleanup EXIT
printf 'temporary data\n' > "$temporary_file"
~~~

脚本正常结束时，EXIT trap 会调用 cleanup。这样即使后面增加了多个退出路径，也不容易忘记删除临时文件。

清理时必须只操作脚本自己创建、并保存在变量中的明确路径，不要对不确定的路径使用递归删除。

### 基础安全习惯

编写脚本时形成以下习惯：

- 变量作为命令参数时加双引号。
- 处理用户输入前先检查参数数量和路径类型。
- 正常数据写标准输出，错误信息写标准错误。
- 重要管道考虑使用 pipefail。
- 临时文件使用 mktemp，不使用固定文件名。
- 临时文件使用完成后清理。
- 调试完成后不要保留 set -x，也不要公开包含敏感信息的追踪输出。
- 删除文件前确认路径来自明确的临时文件变量。

## 示例：带检查和清理的服务报告脚本

下面的脚本展示参数检查、临时文件、错误输出和自动清理：

~~~bash
#!/usr/bin/env bash

set -u
set -o pipefail

if [ "$#" -eq 0 ]; then
  printf 'error: provide at least one service\n' >&2
  exit 1
fi

temporary_file=$(mktemp)
cleanup() {
  rm -f "$temporary_file"
}
trap cleanup EXIT

printf '%s\n' "$@" > "$temporary_file"
sort -u "$temporary_file"
~~~

这个脚本把输入检查、临时文件生命周期、管道安全设置和正常输出分开处理。

## 小结（掌握范围）

本课必须掌握：

- 会使用 bash -n 检查脚本语法。
- 会使用 bash -x 观察脚本实际执行过程，并知道不要暴露敏感信息。
- 知道 set -u 可以发现未设置变量。
- 知道 set -e 可以在未处理的命令失败时停止脚本，但不能替代明确的条件判断。
- 知道 set -o pipefail 可以发现管道前面命令的失败。
- 会使用 >&2 输出错误信息，使用 exit 返回脚本失败状态。
- 能区分函数中的 return 和脚本顶层的 exit。
- 会使用 mktemp 创建临时文件，并使用 trap EXIT 自动清理。
- 能遵守变量加双引号、临时路径明确和删除操作谨慎等基本安全习惯。

## 课后小实操

### 实操一

创建一个带调试入口的路径检查脚本，练习语法检查、执行追踪、参数校验和错误输出。

**操作步骤**

创建 /tmp/bash-course/debug-path.sh，并完成以下要求：

- 脚本必须要求调用者提供一个路径参数。
- 没有参数时，向标准错误输出错误信息，并返回非 0 状态。
- 路径存在时，使用 file 输出文件类型。
- 路径不存在时，向标准错误输出错误信息，并返回非 0 状态。
- 使用 bash -n 检查语法。
- 使用 bash -x 运行一次有效路径，观察变量和命令展开。
- 不要在脚本中写入密码或其他敏感内容。

可以使用已经学过的 $#、if、-e、file、printf、>&2 和 exit。

回到终端执行：

~~~bash
bash -n /tmp/bash-course/debug-path.sh
bash -x /tmp/bash-course/debug-path.sh /etc/hosts
~~~

**代码**

~~~bash
#!/usr/bin/env bash

if [ "$#" -eq 0 ]; then
  printf 'error: path argument is required\n' >&2
  exit 1
fi

if [ -d "$1" ] || [ -f "$1" ]; then
  file "$1"
else
  printf 'directory arg error\n' >&2
  exit 2
fi

~~~

**运行结果**

~~~text
❯ bash -n /tmp/bash-course/debug-path.sh
❯ bash -x /tmp/bash-course/debug-path.sh /etc/hosts
+ '[' 1 -eq 0 ']'
+ '[' -d /etc/hosts ']'
+ '[' -f /etc/hosts ']'
+ file /etc/hosts
/etc/hosts: ASCII text

~~~

### 实操二

创建一个安全的临时报告脚本，练习 set -u、pipefail、mktemp 和 trap 的组合使用。

**操作步骤**

创建 /tmp/bash-course/safe-report.sh，并完成以下要求：

- 开启未设置变量检查和管道失败检查。
- 没有服务参数时，输出错误并返回失败。
- 使用 mktemp 创建中间文件。
- 使用 trap EXIT 清理中间文件。
- 将命令行服务名写入中间文件，排序去重后输出。
- 保留带空格服务名的完整内容。
- 不删除报告目录中的其他文件。

可以使用已经学过的 "$@"、printf、sort -u、重定向、if、exit、mktemp、rm -f 和 trap。

回到终端执行：

~~~bash
bash /tmp/bash-course/safe-report.sh api 'test worker' api database
~~~

**代码**

~~~bash
#!/usr/bin/env bash

set -u
set -o pipefail

if [ "$#" -eq 0 ]; then
  printf 'error: service argument is required\n' >&2
  exit 1
fi

tmpfile=$(mktemp)
cleanup() {
  rm -f "$tmpfile"
}
trap cleanup EXIT
printf '%s\n' "$@" | tee "$tmpfile" | sort -u

~~~

**运行结果**

~~~text
❯ bash /tmp/bash-course/safe-report.sh api 'test worker' api database
api
database
test worker
~~~
