# 位置参数、用户输入与输出

## 引入

上一课中，服务名和环境名直接写在脚本变量里。每次处理不同服务时，都要修改脚本内容，这不够灵活。

Bash 脚本可以从命令行接收参数，也可以在运行过程中等待用户输入。这样，同一个脚本就能处理不同的数据。

本课学习两种输入方式：

- 位置参数：运行脚本时直接把值放在脚本名后面。
- 用户输入：脚本运行后使用 read 等待用户输入。

脚本接收到输入后，仍然使用 printf 输出结果。

## 核心内容

### 使用位置参数接收命令行输入

脚本运行时，脚本名后面的内容会按照顺序保存为位置参数：

~~~bash
#!/usr/bin/env bash

printf 'script: %s\n' "$0"
printf 'first argument: %s\n' "$1"
printf 'second argument: %s\n' "$2"
~~~

如果保存为 /tmp/show-args.sh，这样运行：

~~~bash
bash /tmp/show-args.sh api test
~~~

各个特殊参数的含义是：

| 参数 | 含义 |
| --- | --- |
| $0 | 脚本本身的名称或路径 |
| $1 | 第一个位置参数 |
| $2 | 第二个位置参数 |
| $# | 位置参数的数量 |
| $@ | 所有位置参数 |

位置参数从 $1 开始，$0 保存的是脚本名称，不是第一个业务参数。

### 查看参数数量和处理所有参数

可以使用 $# 查看脚本收到多少个参数：

~~~bash
printf 'argument count: %s\n' "$#"
~~~

如果脚本需要处理数量不固定的参数，可以使用 "$@"。加双引号时，原来的每个参数都会保持为一个独立参数：

~~~bash
printf 'argument: <%s>\n' "$@"
~~~

例如执行：

~~~bash
bash /tmp/show-args.sh 'api gateway' 'test environment'
~~~

"$@" 会保留两个参数中的空格。不要随意写成未加双引号的 $@，否则参数可能因为空格再次被拆分。

### 直接参数和交互输入的区别

位置参数在启动脚本时就已经提供：

~~~bash
bash check-service.sh api production
~~~

这种方式适合自动化任务，因为命令本身已经写清楚了输入。

交互输入则是在脚本运行后由用户输入：

~~~bash
read -r -p 'Service name: ' service
read -r -p 'Environment: ' environment
~~~

read 会等待用户输入并把内容保存到变量中：

- -p：先显示提示文字。
- -r：按原样读取反斜杠，不把反斜杠当作特殊转义。
- 后面的变量名：保存用户输入的变量。

读取后可以正常使用变量：

~~~bash
printf 'service=%s\n' "$service"
printf 'environment=%s\n' "$environment"
~~~

### 为输入选择合适的方式

两种方式各有用途：

| 方式 | 适合场景 |
| --- | --- |
| 位置参数 | 自动化、批处理、命令行工具 |
| read 交互输入 | 临时操作、需要用户现场确认或填写的任务 |

如果脚本要被定时任务或其他脚本调用，通常优先使用位置参数，因为它不需要等待人工输入。

### 输入和输出都要保留边界

位置参数和 read 得到的变量都可能包含空格，因此使用时仍然要加双引号：

~~~bash
printf 'service=%s\n' "$1"
printf 'input=%s\n' "$service"
~~~

输出格式由 printf 控制，数据由双引号包围的变量提供。这样可以避免输入中的空格改变命令参数结构。

## 示例：同时展示命令行参数和交互输入

下面的脚本先读取第一个命令行参数；如果还需要补充信息，再让用户输入环境名称：

~~~bash
#!/usr/bin/env bash

printf 'service from argument: %s\n' "$1"
read -r -p 'Environment: ' environment
printf 'environment from input: %s\n' "$environment"
~~~

运行时：

~~~bash
bash /tmp/service-info.sh api
~~~

脚本会先输出命令行提供的服务名，然后等待你输入环境名称。

## 小结（掌握范围）

本课必须掌握：

- 知道 $0 是脚本名称或路径，$1、$2 等是位置参数。
- 会使用 $# 查看位置参数数量。
- 会使用 "$@" 保留并处理全部位置参数。
- 知道参数中包含空格时必须保留双引号。
- 会使用 read -r -p 读取用户输入并保存到变量。
- 能区分启动脚本时提供的命令行参数和脚本运行后的交互输入。
- 会使用 printf 输出参数和用户输入。

## 课后小实操

### 实操一

创建一个脚本，显示脚本路径、第一个参数、第二个参数、参数数量，并逐个输出所有参数。运行时给参数加入空格，观察 "$@" 是否保持每个参数的完整内容。

**操作步骤**

创建 /tmp/bash-course/show-args.sh，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

printf 'script: %s\n' "$0"
printf 'first argument: %s\n' "$1"
printf 'second argument: %s\n' "$2"
printf 'argument count: %s\n' "$#"
printf 'all arguments:\n'
printf '  %s\n' "$@"
~~~

回到终端执行：

~~~bash
bash /tmp/bash-course/show-args.sh api 'test environment'
~~~

**运行结果**

~~~text
❯ bash /tmp/bash-course/show-args.sh api 'test environment'
script: /tmp/bash-course/show-args.sh
first arg: api
second arg: test environment
arg count: 2
 api
 test environment

~~~

### 实操二

创建一个脚本，运行后让用户输入服务名和环境名，再输出一份简单的信息。

**操作步骤**

创建 /tmp/bash-course/read-input.sh，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

read -r -p 'Service name: ' service
read -r -p 'Environment: ' environment

printf 'service=%s\n' "$service"
printf 'environment=%s\n' "$environment"
~~~

回到终端执行：

~~~bash
bash /tmp/bash-course/read-input.sh
~~~

看到提示后依次输入 api 和 test，每次输入后按回车。

**运行结果**

~~~text
❯ bash /tmp/bash-course/read-input.sh
Service name: hello
Environment: linux
service=hello
environment=linux

~~~
