# 脚本文件与执行方式

## 引入

如果每天都要重复执行一组命令，把命令逐行输入终端容易漏掉步骤，也不方便下次再次使用。Bash 脚本就是一个普通的文本文件，里面按顺序保存要执行的 Shell 命令。

例如，下面两行命令放进脚本后，就可以作为一个整体重复运行：

~~~bash
printf 'collecting information\n'
printf 'check complete\n'
~~~

本课先解决三个基础问题：

- 一个 Bash 脚本文件应该怎样写？
- 为什么文件第一行经常是 `#!/usr/bin/env bash`？
- `bash script.sh` 和 `./script.sh` 有什么区别？

## 核心内容

### Bash 脚本本质上是文本文件

一个最简单的 Bash 脚本可以写成：

~~~bash
#!/usr/bin/env bash

printf 'hello from Bash\n'
printf 'script finished\n'
~~~

第一行叫 **shebang**，由 `#!` 开头，用来声明直接执行这个文件时应该使用哪个解释器。这里的 `env bash` 表示在系统的 `PATH` 中寻找 `bash`。

后面的内容就是按照顺序执行的命令。空行不会产生输出，只是帮助阅读。

脚本文件名通常使用 `.sh` 作为后缀，例如 `backup.sh`，但 `.sh` 只是命名习惯，不是 Bash 判断文件类型的依据。只要内容是 Bash 命令，文件也可以没有扩展名。

### 用 bash 明确执行脚本

假设脚本文件位于 `/tmp/hello-bash.sh`，可以这样运行：

~~~bash
bash /tmp/hello-bash.sh
~~~

这条命令的含义是：

1. 启动 Bash。
2. 让 Bash 读取 `/tmp/hello-bash.sh`。
3. 按文件中的顺序执行命令。

这种方式不要求脚本文件具有可执行权限。即使第一行没有 shebang，只要文件内容是当前 Bash 能理解的命令，`bash script.sh` 仍然可以执行它。

### 直接执行脚本

也可以把脚本当作一个可执行文件直接运行：

~~~bash
chmod +x /tmp/hello-bash.sh
/tmp/hello-bash.sh
~~~

`chmod +x` 给文件增加“可执行”权限。直接执行时，系统会读取脚本第一行的 shebang，找到对应的 Bash 来解释脚本。

如果脚本就在当前目录，通常写成：

~~~bash
./hello-bash.sh
~~~

这里的 `./` 表示“当前目录”。当前目录通常不在 `PATH` 中，所以不能只写 `hello-bash.sh`；明确写出 `./` 可以避免系统误把它当成一个需要在 `PATH` 中查找的命令。

两种执行方式可以这样对比：

| 执行方式 | 是否需要可执行权限 | 使用哪个解释器 |
| --- | --- | --- |
| `bash script.sh` | 不需要 | 命令中明确指定 Bash |
| `./script.sh` | 需要 | 由 shebang 指定 |

### 脚本是在另一个 Bash 进程中运行的

从终端执行脚本时，通常会启动一个新的 Bash 进程来运行它。脚本中的命令会依次执行，但脚本结束后，脚本内部的临时状态不会自动变成当前终端的状态。

本课先记住执行边界即可：`bash script.sh` 的重点是“让 Bash 读取并执行文件”，不是把文件内容直接粘贴进当前 Shell。变量和当前 Shell 状态的细节会在后续课程中学习。

### 使用路径运行脚本

脚本可以使用绝对路径或相对路径：

~~~bash
/tmp/hello-bash.sh
~~~

如果当前目录中有脚本，则使用：

~~~bash
./hello-bash.sh
~~~

如果脚本所在目录已经加入 `PATH`，才可以直接写脚本名执行。学习阶段优先使用明确的路径，便于确认运行的到底是哪一个文件。

## 示例：创建并运行一个最小脚本

先创建练习目录：

~~~bash
mkdir -p /tmp/bash-course
~~~

创建 `/tmp/bash-course/hello-bash.sh`，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

printf 'first run\n'
printf 'second run\n'
~~~

然后分别执行：

~~~bash
bash /tmp/bash-course/hello-bash.sh

chmod +x /tmp/bash-course/hello-bash.sh
/tmp/bash-course/hello-bash.sh
~~~

前两次输出来自同一个脚本，只是执行方式不同。`chmod +x` 不会修改脚本内容，只会改变文件的权限。

## 小结（掌握范围）

本课必须掌握：

- 知道 Bash 脚本是按顺序保存 Shell 命令的文本文件。
- 知道 shebang `#!/usr/bin/env bash` 用于声明直接执行脚本时使用的解释器。
- 会使用 `bash script.sh` 执行脚本，并知道这种方式不要求可执行权限。
- 会使用 `chmod +x script.sh` 添加可执行权限。
- 会使用 `./script.sh` 或明确路径直接执行脚本。
- 知道 `./` 表示当前目录，脚本文件名后缀 `.sh` 只是命名习惯。
- 能区分“由命令指定 Bash 执行”和“由 shebang 指定解释器”的两种执行方式。

## 课后小实操

### 实操一

创建一个最小 Bash 脚本，再用 bash 命令执行它。观察脚本中的两条 printf 命令是否会按顺序输出。

**操作步骤**

~~~bash
mkdir -p /tmp/bash-course
~~~

创建 `/tmp/bash-course/first.sh`，并将下面的内容写入文件：

~~~bash
#!/usr/bin/env bash

printf 'step one\n'
printf 'step two\n'
~~~

回到终端执行：

~~~bash
bash /tmp/bash-course/first.sh
~~~

**运行结果**

~~~text
❯ bash /tmp/bash-course/first.sh
step one
step two

~~~

### 实操二

将刚才的脚本内容修改为下面这样并保存，在末尾增加一行 printf 命令，再为脚本增加可执行权限，最后使用明确路径直接运行。这个练习用于对比 `bash script.sh` 和直接执行的区别。

**操作步骤**

将 `/tmp/bash-course/first.sh` 的内容修改为下面这样并保存：

~~~bash
#!/usr/bin/env bash

printf 'step one\n'
printf 'step two\n'
printf 'direct execution\n'
~~~

回到终端执行：

~~~bash
chmod +x /tmp/bash-course/first.sh
/tmp/bash-course/first.sh
~~~

**运行结果**

~~~text
❯ /tmp/bash-course/first.sh
step one
step two
direct execution

~~~
