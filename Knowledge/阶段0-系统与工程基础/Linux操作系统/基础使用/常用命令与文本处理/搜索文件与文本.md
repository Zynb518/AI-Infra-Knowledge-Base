# 搜索文件与文本

## 引入

在 Linux 中，“搜索”通常对应两个不同问题：

- 文件或目录在哪里？
- 哪些文本行包含目标内容？

`find` 根据名称、类型和位置等条件查找文件系统对象；`grep` 在文本文件或命令输出中查找匹配内容。先分清搜索对象，再选择命令，可以避免把复杂任务写成难以理解的长命令。

## 核心内容

### 先判断要搜索什么

| 搜索目标 | 推荐方式 |
| --- | --- |
| 文件名、目录名或文件类型 | `find` |
| 文件内部的文本 | `grep` |
| 命令输出中的文本 | 管道连接 `grep` |
| 目录下多个文件的内容 | `grep -r` 或 `grep -R` |

`find` 输出的是路径，`grep` 输出的是包含匹配内容的文本行。两者名字相近，但解决的问题不同。

### 用 `grep` 搜索文本

`grep` 的基本形式是：

~~~text
grep [选项] '搜索模式' 文件
~~~

例如，在日志中查找包含 `ERROR` 的行：

~~~bash
grep 'ERROR' app.log
~~~

默认情况下，`grep` 区分大小写，只显示匹配到的完整行。

搜索模式通常应该放在引号中，避免空格或特殊字符被 Shell 提前解释：

~~~bash
grep 'connection failed' app.log
~~~

### 显示行号和忽略大小写

`-n` 会显示匹配行的行号：

~~~bash
grep -n 'ERROR' app.log
~~~

`-i` 会忽略大小写：

~~~bash
grep -i 'error' app.log
~~~

选项可以组合：

~~~bash
grep -n -i 'error' app.log
~~~

这条命令会匹配 `ERROR`、`Error` 和 `error`，并显示所在行号。

### 排除匹配内容

`-v` 会反向选择，只显示不匹配的行：

~~~bash
grep -v 'DEBUG' app.log
~~~

这适合临时过滤噪声，例如从日志中排除大量调试信息。

### 按普通字符串搜索

`grep` 默认把搜索模式当作正则表达式，部分字符具有特殊含义，例如 `.`、`*` 和 `[]`。

如果只想按原样搜索字符串，可以使用 `-F`：

~~~bash
grep -F 'user[id]' app.log
~~~

`-F` 表示 fixed strings，即固定字符串，不把方括号等字符解释为正则表达式。

本课不深入正则表达式，只需要知道：搜索内容包含特殊符号时，`grep -F` 通常更符合“按原文查找”的预期。

### 递归搜索目录内容

`-r` 会递归读取目录中的文件：

~~~bash
grep -r -n 'ERROR' logs/
~~~

输出通常包含文件路径、行号和匹配文本：

~~~text
logs/app.log:12:ERROR disk full
~~~

如果只想搜索某类文件，可以配合 `--include`：

~~~bash
grep -r -n --include='*.md' 'Shell' .
~~~

这里：

- `.` 表示从当前目录开始。
- `--include='*.md'` 只检查名称匹配 `*.md` 的文件。
- `'*.md'` 必须加引号，避免 Shell 在 `grep` 运行前提前展开。

### 在命令输出中搜索

`grep` 可以从标准输入读取内容，因此常放在管道右侧：

~~~bash
ls --help | grep 'sort'
~~~

`ls --help` 产生帮助文本，管道把文本交给 `grep`，最终只显示包含 `sort` 的行。

这种方式不会修改原始输出来源，只是从数据流中筛选需要的内容。

### `grep` 的退出状态

`grep` 的退出状态很有实际意义：

| 状态 | 含义 |
| --- | --- |
| `0` | 找到了匹配内容 |
| `1` | 没有找到匹配内容 |
| `2` 或其他非零值 | 发生读取、参数等错误 |

例如：

~~~bash
grep 'ERROR' app.log
printf '退出状态：%s\n' "$?"
~~~

“没有匹配”不一定是程序故障，但它会返回 1，方便 Bash 脚本根据搜索结果决定后续操作。

### 用 `find` 查找文件和目录

`find` 的基本形式是：

~~~text
find 起始路径 条件
~~~

从当前目录查找所有 Markdown 文件：

~~~bash
find . -name '*.md'
~~~

`find` 会从 `.` 开始递归向下搜索，并输出匹配路径。

`'*.md'` 必须加引号。这样通配符会原样交给 `find`，由 `find` 在每个目录中匹配文件名；如果不加引号，Shell 可能先把它展开成当前目录中的文件。

### 按类型和名称查找

`-type f` 只匹配普通文件：

~~~bash
find . -type f
~~~

`-type d` 只匹配目录：

~~~bash
find . -type d
~~~

条件可以组合，默认表示同时满足：

~~~bash
find . -type f -name '*.md'
~~~

这表示从当前目录开始，只查找名称以 `.md` 结尾的普通文件。

`-iname` 与 `-name` 类似，但忽略大小写：

~~~bash
find . -type f -iname '*.md'
~~~

它既能匹配 `notes.md`，也能匹配 `GUIDE.MD`。

### 限制搜索深度

GNU/Linux 中常用 `-maxdepth` 限制向下搜索的层数：

~~~bash
find . -maxdepth 2 -type f
~~~

`-maxdepth 2` 表示只查看起始位置及其向下两层范围，适合先缩小结果数量。

本课只使用 `find` 查看路径，不使用 `-delete` 等删除动作。先确认搜索结果，再进行任何修改或清理操作。

### `find` 与 `grep` 如何配合思考

遇到任务时，可以先问：

~~~text
我要找的是路径吗？
  是 → find

我要找的是文件里的某段文字吗？
  是 → grep

我要在整个目录中搜索文字吗？
  是 → grep -r
~~~

例如，“查找所有 Markdown 文件”使用 `find`；“查找哪些 Markdown 文件提到了 Shell”使用带 `--include` 的递归 `grep`。

## 示例：查找日志文件中的错误

先准备两个临时日志：

~~~bash
mkdir -p /tmp/search-example
printf 'INFO service started\nERROR disk full\n' > /tmp/search-example/app.log
printf 'INFO worker ready\n' > /tmp/search-example/worker.log
~~~

查找日志文件路径：

~~~bash
find /tmp/search-example -type f -name '*.log'
~~~

再搜索日志内容：

~~~bash
grep -r -n 'ERROR' /tmp/search-example
~~~

`find` 回答“有哪些日志文件”，`grep` 回答“错误出现在哪个文件、哪一行”。

## 小结（掌握范围）

本课必须掌握：

- 能根据搜索目标选择 `find` 或 `grep`。
- 会使用 `grep '模式' 文件` 搜索文本。
- 会使用 `-n`、`-i`、`-v` 和 `-F` 完成常见筛选。
- 会使用 `grep -r` 递归搜索目录内容。
- 知道 `grep` 返回 0 表示匹配，1 表示没有匹配。
- 会使用 `find 起始路径 -type f -name '模式'` 查找文件。
- 能区分 `-name` 和忽略大小写的 `-iname`。
- 理解 `find` 中的文件名通配符需要加引号。
- 先使用 `find` 查看结果，不直接使用具有删除效果的动作。

## 课后小实操

### 实操一

创建两份临时日志，使用 `grep` 查找错误、忽略大小写搜索，并递归筛选目录内容。

**操作步骤**

~~~bash
mkdir -p /tmp/text-search-practice
printf 'INFO service started\nERROR disk full\nDEBUG retry scheduled\n' > /tmp/text-search-practice/app.log
printf 'INFO worker ready\nerror task failed\n' > /tmp/text-search-practice/worker.log

grep -n 'ERROR' /tmp/text-search-practice/app.log
grep -r -n -i 'error' /tmp/text-search-practice
grep -r -n -v 'DEBUG' /tmp/text-search-practice
~~~

**运行结果**

~~~shell
❯ mkdir -p /tmp/text-search-practice
❯ printf 'INFO service started\nERROR disk full\nDEBUG retry scheduled\n' > /tmp/text-search-practice/app.log
❯ printf 'INFO worker ready\nerror task failed\n' > /tmp/text-search-practice/worker.log
❯ grep -n 'ERROR' /tmp/text-search-practice/app.log
2:ERROR disk full
❯ grep -nri 'error' /tmp/text-search-practice/
/tmp/text-search-practice/app.log:2:ERROR disk full
/tmp/text-search-practice/worker.log:2:error task failed
❯ grep -n -r -i 'error' /tmp/text-search-practice/
/tmp/text-search-practice/app.log:2:ERROR disk full
/tmp/text-search-practice/worker.log:2:error task failed
❯ grep -r -n -v 'DEBUG' /tmp/text-search-practice
/tmp/text-search-practice/app.log:1:INFO service started
/tmp/text-search-practice/app.log:2:ERROR disk full
/tmp/text-search-practice/worker.log:1:INFO worker ready
/tmp/text-search-practice/worker.log:2:error task failed

~~~

### 实操二

创建不同类型和大小写扩展名的文件，使用 `find` 按类型与名称查找。

**操作步骤**

~~~bash
mkdir -p /tmp/file-search-practice/docs /tmp/file-search-practice/logs
touch /tmp/file-search-practice/docs/readme.md
touch /tmp/file-search-practice/docs/guide.MD
touch /tmp/file-search-practice/logs/app.log

find /tmp/file-search-practice -type f
find /tmp/file-search-practice -type f -name '*.md'
find /tmp/file-search-practice -type f -iname '*.md'
~~~

**运行结果**

~~~text
❯ find /tmp/file-search-practice -type f -name '*.md'
/tmp/file-search-practice/docs/readme.md
❯ find /tmp/file-search-practice -type f -name '*.md'
/tmp/file-search-practice/docs/readme.md
❯ find /tmp/file-search-practice -type f -iname '*.md'
/tmp/file-search-practice/docs/readme.md
/tmp/file-search-practice/docs/guide.MD

~~~
