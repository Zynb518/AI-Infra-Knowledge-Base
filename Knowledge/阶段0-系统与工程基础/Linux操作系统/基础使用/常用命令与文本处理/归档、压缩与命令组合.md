# 归档、压缩与命令组合

## 引入

当我们需要把一组配置文件、日志或项目资料发送给别人时，逐个处理文件很麻烦。更常见的做法是先把多个文件整理成一个文件，再根据需要压缩体积。

这里有两个容易混淆的动作：

- **归档**：把多个文件和目录收集到一个文件中，主要解决“方便携带和管理”的问题。
- **压缩**：减少数据占用的空间，主要解决“文件更小”的问题。

Linux 中最常用的工具是 `tar`。它既能创建归档，也能在创建或解开归档时调用 `gzip` 等压缩方式，所以经常看到 `.tar.gz` 或 `.tgz` 文件。

## 核心内容

### 只归档：创建、查看和解开 `.tar`

创建一个未压缩的归档：

~~~
tar -cf project.tar project/
~~~

选项的含义是：

- `c`：create，创建归档。
- `f`：指定归档文件，`f` 后面紧跟归档文件名。

归档完成后，可以先查看其中有哪些路径，而不解开文件：

~~~
tar -tf project.tar
~~~

这里的 `t` 是 list，表示列出归档内容。

解开归档：

~~~
tar -xf project.tar
~~~

这里的 `x` 是 extract，表示提取归档内容。

因此，最常见的三个动作可以记成：

| 命令 | 作用 |
| --- | --- |
| `tar -cf archive.tar source/` | 创建归档 |
| `tar -tf archive.tar` | 查看归档内容 |
| `tar -xf archive.tar` | 解开归档 |

### 归档并压缩：创建 `.tar.gz`

使用 `z` 选项调用 gzip，在创建归档的同时压缩：

~~~
tar -czf project.tar.gz project/
~~~

此时：

- `c` 仍然表示创建。
- `z` 表示使用 gzip 压缩。
- `f` 后面仍然是归档文件名。

查看压缩归档中的文件，需要同时写上 `z`：

~~~
tar -tzf project.tar.gz
~~~

解开 `.tar.gz` 文件：

~~~
tar -xzf project.tar.gz
~~~

文件名后缀是约定，不是命令判断文件的唯一依据。需要确认一个文件是否确实是 gzip 压缩的 tar 归档，可以使用已经学过的 `file`：

~~~
file project.tar.gz
~~~

### 指定解压目录

默认情况下，`tar -xf` 会把内容解开到当前目录。为了避免文件散落在当前目录，通常使用 `-C` 指定目标目录：

~~~
mkdir -p /tmp/project-extracted
tar -xzf project.tar.gz -C /tmp/project-extracted
~~~

`-C` 后面的目录必须已经存在。解压未知来源的归档时，先用 `tar -tzf` 预览内容，再解压到单独的临时目录，是更稳妥的做法。

### 让归档内容更容易管理

创建归档时，可以通过 `-C` 控制归档内路径的起点：

~~~
tar -czf project.tar.gz -C /tmp project
~~~

如果 `/tmp/project` 存在，这个命令会把 `project/` 目录放进归档，而不会把创建归档时的绝对路径写进去。归档内通常应保留清晰、相对的路径，便于别人解压和使用。

### 把 `tar` 的输出交给其他命令

`tar -t` 会把归档中的路径输出到标准输出，因此可以继续使用管道交给其他文本命令：

~~~
tar -tzf project.tar.gz | sort
~~~

如果只想检查归档里是否有日志文件，可以继续筛选：

~~~
tar -tzf project.tar.gz | grep '\.log$'
~~~

这里并没有先把归档全部解开，而是把 `tar` 列出的路径直接交给 `sort` 或 `grep`。这就是“命令组合”：一个命令的输出成为下一个命令的输入。

## 示例：打包一组配置文件

下面的命令在 `/tmp` 下创建练习目录，把配置文件和说明文件打包成一个 gzip 压缩归档，然后先查看归档内容：

~~~
mkdir -p /tmp/service-package/config
printf 'port=8080\n' > /tmp/service-package/config/app.conf
printf 'service package practice\n' > /tmp/service-package/README.txt

tar -czf /tmp/service-package.tar.gz -C /tmp service-package
tar -tzf /tmp/service-package.tar.gz
~~~

可能看到：

~~~
service-package/
service-package/config/
service-package/config/app.conf
service-package/README.txt
~~~

可以看到，归档保存了目录结构；`tar -tzf` 只列出内容，不会在当前目录生成文件。

## 小结（掌握范围）

本课必须掌握：

- 能区分归档和压缩：归档是收集多个路径，压缩是减少数据体积。
- 会使用 `tar -cf` 创建未压缩归档。
- 会使用 `tar -tf` 预览归档内容。
- 会使用 `tar -xf` 解开归档。
- 会使用 `tar -czf` 创建 `.tar.gz` 压缩归档。
- 会使用 `tar -tzf` 查看 `.tar.gz` 内容，使用 `tar -xzf` 解压。
- 知道 `c`、`t`、`x`、`z`、`f` 和 `-C` 的基本作用。
- 解压未知归档前会先预览内容，并优先解压到单独目录。
- 能把 `tar -t` 的输出通过管道交给 `sort`、`grep` 等命令继续处理。

## 课后小实操

### 实操一

创建一组本地练习文件，打包成 `.tar.gz`，然后查看归档内的目录结构。这个练习用于熟悉“创建”和“查看”两个动作。

**操作步骤**

~~~
mkdir -p /tmp/tar-practice/source/logs
printf 'app started\n' > /tmp/tar-practice/source/app.log
printf 'port=8080\n' > /tmp/tar-practice/source/config.ini
printf 'request ok\n' > /tmp/tar-practice/source/logs/access.log

tar -czf /tmp/tar-practice.tar.gz -C /tmp/tar-practice source
tar -tzf /tmp/tar-practice.tar.gz
file /tmp/tar-practice.tar.gz
~~~

**运行结果**

~~~text
❯ mkdir -p /tmp/tar-practice/source/logs
❯ printf 'app started\n' > /tmp/tar-practice/source/app.log
❯ printf 'port=8000\n' > /tmp/tar-practice/source/config.ini
❯ printf 'request ok\n' > /tmp/tar-practice/source/logs/access.log
❯ tar -czf /tmp/tar-practice.tar.gz -C /tmp/tar-practice source
❯ tar -tzf /tmp/tar-practice.tar.gz
source/
source/logs/
source/logs/access.log
source/app.log
source/config.ini
❯ file /tmp/tar-practice.tar.gz
/tmp/tar-practice.tar.gz: gzip compressed data, from Unix, original size modulo 2^32 10240

~~~

### 实操二

把刚才创建的归档解压到单独目录，再通过 `find` 和 `sort` 检查解压结果。这个练习用于熟悉“指定目录解压”和命令组合。

**操作步骤**

~~~
mkdir -p /tmp/tar-practice/extracted
tar -xzf /tmp/tar-practice.tar.gz -C /tmp/tar-practice/extracted
find /tmp/tar-practice/extracted -type f -print | sort
~~~

**运行结果**

~~~text
❯ mkdir -p /tmp/tar-practice/extracted
❯ tar -xzf /tmp/tar-practice.tar.gz -C /tmp/tar-practice/extracted
❯ find /tmp/tar-practice/extracted -type f -print | sort
/tmp/tar-practice/extracted/source/app.log
/tmp/tar-practice/extracted/source/config.ini
/tmp/tar-practice/extracted/source/logs/access.log
~~~
