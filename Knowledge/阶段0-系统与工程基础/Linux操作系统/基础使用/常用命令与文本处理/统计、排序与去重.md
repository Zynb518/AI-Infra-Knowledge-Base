 # 统计、排序与去重

## 引入

日志、清单和命令输出经常包含大量重复文本。只查看内容还不够，我们通常还需要回答：

- 一共有多少行？
- 哪些值重复出现？
- 每个值出现了多少次？
- 哪个数字最大或最小？

`wc` 负责统计，`sort` 负责排序，`uniq` 负责处理相邻重复行。三者通过管道组合后，可以完成很多日志分析和数据整理任务。

## 核心内容

### 用 `wc` 统计文本

`wc` 是 word count 的缩写。直接读取文件时：

~~~bash
wc example.txt
~~~

通常会输出：

~~~text
行数  单词数  字节数  文件名
~~~

常用选项包括：

| 选项 | 作用 |
| --- | --- |
| `-l` | 统计行数 |
| `-w` | 统计按空白分隔的单词数 |
| `-c` | 统计字节数 |
| `-m` | 统计字符数 |

例如：

~~~bash
wc -l app.log
wc -w article.txt
wc -c data.txt
wc -m data.txt
~~~

`wc -c` 统计字节，`wc -m` 统计字符。UTF-8 中文字符通常占多个字节，因此两者结果可能不同。

`wc -w` 按空格、制表符和换行等空白划分单词。没有空格分隔的中文句子，通常不会按汉字数量统计为多个“单词”。

### 从管道统计行数

`wc` 可以从标准输入读取文本：

~~~bash
printf 'api\nworker\napi\n' | wc -l
~~~

`printf` 产生三行内容，`wc -l` 输出 `3`。

这种写法常用于统计命令结果：

~~~bash
find . -type f | wc -l
grep -r 'ERROR' logs/ | wc -l
~~~

第一条统计找到的文件路径数量，第二条统计包含匹配结果的输出行数。

### 用 `sort` 排序文本

`sort` 默认按整行文本排序：

~~~bash
printf 'banana\napple\ncherry\n' | sort
~~~

输出为：

~~~text
apple
banana
cherry
~~~

`sort` 默认只把排序结果写到标准输出，不会修改原文件。

### 数字排序与逆序

默认排序主要按文本规则进行。对于数字：

~~~bash
printf '2\n10\n3\n' | sort
~~~

文本排序可能得到：

~~~text
10
2
3
~~~

因为字符 `1` 排在 `2` 前面。使用 `-n` 才会按数值排序：

~~~bash
printf '2\n10\n3\n' | sort -n
~~~

结果是：

~~~text
2
3
10
~~~

`-r` 表示 reverse，即逆序：

~~~bash
printf '2\n10\n3\n' | sort -nr
~~~

`-nr` 等价于同时使用 `-n` 和 `-r`，结果从大到小排列。

### 按指定列排序

文本由空白分隔成多列时，可以使用 `-k` 指定排序字段：

~~~bash
printf 'api 120\nworker 45\ndatabase 300\n' | sort -k2,2n
~~~

`-k2,2n` 表示：

- 从第 2 列开始排序。
- 在第 2 列结束排序键。
- 使用数字顺序。

结果会按照 `45`、`120`、`300` 排列。若希望从大到小：

~~~bash
printf 'api 120\nworker 45\ndatabase 300\n' | sort -k2,2nr
~~~

这里的 `r` 表示逆序。

### 用 `uniq` 处理相邻重复行

`uniq` 只比较相邻的行：

~~~bash
printf 'api\napi\nworker\n' | uniq
~~~

输出为：

~~~text
api
worker
~~~

但如果重复行不相邻：

~~~bash
printf 'api\nworker\napi\n' | uniq
~~~

两个 `api` 都会保留，因为它们之间隔着 `worker`。

这是使用 `uniq` 时最重要的规则：

> `uniq` 只能合并相邻重复行，不会主动搜索整个输入中的重复值。

### 为什么常用 `sort | uniq`

先排序可以让相同内容相邻：

~~~bash
printf 'api\nworker\napi\n' | sort | uniq
~~~

输出为：

~~~text
api
worker
~~~

如果只需要排序并去重，也可以使用：

~~~bash
printf 'api\nworker\napi\n' | sort -u
~~~

`sort -u` 相当于在排序时只保留每个值的一份。

### 统计每个值出现次数

`uniq -c` 会在每组相邻重复行前显示出现次数：

~~~bash
printf 'api\nworker\napi\napi\n' | sort | uniq -c
~~~

结果类似：

~~~text
      3 api
      1 worker
~~~

如果希望按出现次数从高到低排列：

~~~bash
printf 'api\nworker\napi\napi\n' | sort | uniq -c | sort -nr
~~~

处理过程是：

~~~text
原始数据
   ↓ sort
相同内容相邻
   ↓ uniq -c
统计每组次数
   ↓ sort -nr
按次数从大到小排序
~~~

这是一种常见的频次统计管道。

### `uniq` 的常用选项

| 选项 | 作用 |
| --- | --- |
| `-c` | 显示每组相邻行的出现次数 |
| `-d` | 只显示出现过多次的行 |
| `-u` | 只显示仅出现一次的行 |

这些选项通常也应在排序后使用：

~~~bash
sort values.txt | uniq -d
sort values.txt | uniq -u
~~~

### 三个容易混淆的地方

1. `wc -c` 统计字节，不等于字符数量；字符数量使用 `wc -m`。
2. `sort` 默认按文本排序，数字排序需要 `-n`。
3. `uniq` 只处理相邻重复行，统计全局重复值通常先执行 `sort`。

## 示例：统计服务名称出现频率

先准备一份服务访问记录：

~~~bash
printf 'api\nworker\napi\ndatabase\napi\nworker\n' > /tmp/service-access.txt
~~~

统计总行数：

~~~bash
wc -l < /tmp/service-access.txt
~~~

统计每个服务出现次数，并按次数从高到低排列：

~~~bash
sort /tmp/service-access.txt | uniq -c | sort -nr
~~~

这个管道可以用于统计日志中的状态码、客户端地址、服务名称或错误类型。

## 小结（掌握范围）

本课必须掌握：

- 会使用 `wc -l`、`wc -w`、`wc -c` 和 `wc -m`。
- 能区分字节数与字符数。
- 会使用 `sort` 对文本行排序。
- 知道数字排序需要 `sort -n`，逆序使用 `-r`。
- 能看懂 `sort -k2,2n` 按第二列数字排序。
- 理解 `uniq` 只处理相邻重复行。
- 会使用 `sort | uniq` 完成全局去重。
- 会使用 `uniq -c` 统计出现次数。
- 会使用 `sort | uniq -c | sort -nr` 完成频次排行。

## 课后小实操

### 实操一

统计一组服务访问记录的总行数、唯一服务和出现频率。

**操作步骤**

~~~bash
printf 'api\nworker\napi\ndatabase\napi\nworker\n' > /tmp/count-sort-practice.txt

wc -l < /tmp/count-sort-practice.txt
sort /tmp/count-sort-practice.txt
sort /tmp/count-sort-practice.txt | uniq
sort /tmp/count-sort-practice.txt | uniq -c
sort /tmp/count-sort-practice.txt | uniq -c | sort -nr
~~~

**运行结果**

~~~text
❯ wc -l < /tmp/count-sort-practice.txt
6
❯ sort /tmp/count-sort-practice.txt
api
api
api
database
worker
worker
❯ sort /tmp/count-sort-practice.txt | uniq
api
database
worker
❯ sort /tmp/count-sort-practice.txt -u
api
database
worker
❯ sort /tmp/count-sort-practice.txt | uniq -c
      3 api
      1 database
      2 worker
❯ sort /tmp/count-sort-practice.txt | uniq -c | sort -nr
      3 api
      2 worker
      1 database

~~~

### 实操二

根据第二列延迟数值，对服务记录进行升序和降序排列。

**操作步骤**

~~~bash
printf 'api 120\nworker 45\ndatabase 300\ncache 80\n' > /tmp/service-latency.txt

sort -k2,2n /tmp/service-latency.txt
sort -k2,2nr /tmp/service-latency.txt
~~~

**运行结果**

~~~text
❯ sort -k2,2n /tmp/service-latency.txt
worker 45
cache 80
api 120
database 300
❯ sort -k2,2nr /tmp/service-latency.txt
database 300
api 120
cache 80
worker 45

~~~
