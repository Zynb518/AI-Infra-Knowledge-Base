# TTY、PTY 与交互式会话

## 引入

打开终端窗口后，我们可以输入命令、看到输出，还能用 `Ctrl-C` 中断前台任务。终端模拟器和 Shell 是两个独立程序，它们之间需要一条既能传递字符、又能支持作业控制的通道。

现代桌面终端、SSH 和终端复用工具通常通过 PTY 提供这条通道。本课从当前终端连接入手，逐步解释 TTY、PTY、`/dev/pts/N` 和交互式会话之间的关系。

## 核心内容

### 从终端窗口到 Shell

先建立一个简化模型：

~~~text
键盘与屏幕
      ↕
终端模拟器
      ↕
PTY master
      ↕
PTY slave：/dev/pts/N
      ↕
Shell 与前台任务
~~~

输入方向大致是：

1. 终端模拟器接收键盘输入。
2. 输入通过 PTY master 进入 PTY slave。
3. Shell 或当前前台任务从 PTY slave 读取输入。

输出方向相反：

1. Shell 或程序把内容写入 PTY slave。
2. 终端模拟器从 PTY master 读取内容。
3. 终端窗口把字符显示在屏幕上。

这个模型先帮助理解各部分的职责，不要求记忆内核实现细节。

### TTY 是什么

TTY 最初来自 teletypewriter，也就是早期的电传打字终端。现代 Linux 中，TTY 更重要的含义是内核提供的一套终端设备接口。

TTY 不只是传递字符，还参与：

- 保存终端的输入模式。
- 记录窗口大小。
- 识别部分控制字符。
- 区分当前前台任务。
- 配合作业控制发送信号。

常见的终端设备包括：

| 路径 | 常见含义 |
| --- | --- |
| `/dev/tty1` | Linux 本机虚拟控制台 |
| `/dev/ttyS0` | 串口终端 |
| `/dev/pts/0` | 伪终端的 slave 端 |

因此，TTY 是一个更大的终端接口概念，不等同于桌面上的终端窗口。

### PTY 是什么

PTY 是 pseudo-terminal，也就是伪终端。它完全由软件创建，通常成对出现：

- PTY master：由终端模拟器、SSH 服务端或终端复用工具控制。
- PTY slave：表现得像普通 TTY，提供给 Shell 和前台程序使用。

在日常使用中，Shell 通常只看到 slave 端，例如 `/dev/pts/0`。它不需要知道另一端是 GNOME Terminal、SSH 服务还是其他程序。

可以把 PTY 理解为一根双向的“虚拟终端线”，它让软件中的终端窗口和 Shell 像连接真实终端一样交互。

### TTY 与 PTY 的关系

两者的关系可以概括为：

~~~text
TTY：Linux 的终端接口和行为模型
PTY：用软件实现的一类 TTY，由 master 和 slave 组成
~~~

也就是说，PTY 不是与 TTY 完全并列的另一个概念，而是现代系统中实现终端会话的常见方式。

### 用 `tty` 查看当前终端

`tty` 命令检查标准输入是否连接到终端，并显示对应设备：

~~~bash
tty
~~~

在桌面终端或 SSH 交互会话中，常见结果是：

~~~text
/dev/pts/0
~~~

这表示当前命令的标准输入连接到伪终端 slave 设备。最后的编号由系统分配，不同终端窗口通常会得到不同编号。

`tty` 检查的是标准输入。即使输出最终显示在终端，只要标准输入来自管道或文件，它仍可能报告 `not a tty`，或者显示本地化后的同类提示。

### 用 `ps` 观察 Shell 与终端

`ps` 用来查看进程信息。下面的命令只查看当前 Shell：

~~~bash
ps -p "$$" -o pid,tty,comm
~~~

各部分含义是：

- `ps`：显示进程信息。
- `-p "$$"`：只选择 PID 为 `$$` 的进程；`$$` 表示当前 Shell 的进程号。
- `-o pid,tty,comm`：只显示 PID、TTY 和命令名称三列。

结果可能类似：

~~~text
    PID TT       COMMAND
  12345 pts/0    zsh
~~~

在普通交互式终端中，`pts/0` 与 `tty` 输出的 `/dev/pts/0` 通常对应同一个终端连接，只是 `ps` 省略了设备路径前缀。

如果 `ps` 的 TTY 列显示 `?`，表示该进程没有控制终端。容器、自动化任务或某些集成终端环境可能出现这种情况，即使它的标准输入连接到了某种终端设备。`tty` 查看标准输入设备，`ps` 的 TTY 列查看控制终端，两者关注点并不完全相同。

这条命令曾经不适合放在最初的概念课中；学过进程号、作业控制和 TTY 后，现在只需要掌握它用于确认“当前 Shell 连接到哪个终端”。

### 为什么管道中会出现 `not a tty`

直接运行：

~~~bash
tty
~~~

标准输入来自终端，因此会显示 `/dev/pts/N`。

如果把管道连接到 `tty`：

~~~bash
printf 'test\n' | tty
~~~

`tty` 的标准输入变成了管道，不再是终端设备，因此会报告 `not a tty`。

这时错误提示仍可能显示在终端，因为它的标准输出仍然连接着终端。标准输入和标准输出是两条独立通道，不能因为输出显示在屏幕上，就认定输入也来自 TTY。

### 交互式与非交互式会话

交互式 Shell 面向用户操作，通常具有这些特征：

- 显示提示符。
- 从终端读取命令。
- 支持历史记录和补全。
- 支持前台、后台和作业控制。

非交互式 Shell 通常用于执行脚本或单条命令：

~~~bash
sh -c 'printf "hello\n"'
~~~

`sh -c` 表示让 `sh` 执行后面的命令字符串。它完成任务后直接退出，通常不显示交互提示符，也不需要用户逐条输入命令。

交互式和“是否连接 TTY”关系密切，但不是完全相同的概念。Shell 是否采用交互模式由启动方式决定，而 `tty` 只检查当前标准输入是不是终端。

### SSH 为什么有时需要 PTY

直接登录远程主机时：

~~~bash
ssh server
~~~

SSH 通常会为交互会话分配一个远程 PTY，远程 Shell 因而能显示提示符、接收控制键并使用作业控制。

执行单条远程命令时：

~~~bash
ssh server 'some-command'
~~~

SSH 通常不需要分配 PTY，因为命令可以通过普通数据通道运行。

某些必须在终端中运行的远程程序，可以使用 `-t` 请求分配 PTY：

~~~bash
ssh -t server 'some-command'
~~~

本课只需要理解 `-t` 与“请求远程终端环境”有关，不要求在没有远程服务器时进行实操。

### TTY 如何参与 `Ctrl-C` 和 `Ctrl-Z`

TTY 会记录当前的前台任务。当终端识别到 `Ctrl-C` 或 `Ctrl-Z` 时，会把相应信号发送给当前前台任务：

~~~text
Ctrl-C → TTY → 前台任务 → SIGINT
Ctrl-Z → TTY → 前台任务 → SIGTSTP
~~~

这解释了为什么控制键通常影响前台任务，而不会随意作用于同一 Shell 中所有后台任务。

Shell 的 `fg` 和 `bg` 会改变作业状态；TTY 则帮助确定哪个任务当前处于前台并接收终端产生的信号。

## 示例：确认当前 Shell 使用的终端

~~~bash
printf '标准输入对应的终端：\n'
tty

printf '当前 Shell 进程：\n'
ps -p "$$" -o pid,tty,comm
~~~

如果 `tty` 显示 `/dev/pts/2`，而 `ps` 的 TTY 列显示 `pts/2`，就说明当前 Shell 的标准输入和控制终端对应同一个 PTY slave。如果 TTY 列显示 `?`，则说明当前运行环境没有为该 Shell 设置控制终端。

## 小结（掌握范围）

本课必须掌握：

- 能区分终端模拟器、TTY、PTY 和 Shell。
- 知道 PTY 由 master 与 slave 两端组成。
- 知道 Shell 和前台程序通常连接 PTY slave，常见路径是 `/dev/pts/N`。
- 会使用 `tty` 查看标准输入连接的终端。
- 会使用 `ps -p "$$" -o pid,tty,comm` 查看当前 Shell 的 PID、TTY 和名称。
- 理解 `not a tty` 表示标准输入不是终端设备。
- 能区分交互式 Shell 和非交互式 Shell。
- 知道 SSH 的 `-t` 用于请求远程 PTY。
- 理解 `Ctrl-C` 和 `Ctrl-Z` 通常由 TTY 转换为发送给前台任务的信号。
