# Shell 如何解析一条命令

## 引入

你输入的一行命令，Shell 通常不会原样交给程序。它会先根据空格、引号和转义符区分参数，再展开变量、执行命令替换，最后把处理后的结果交给目标命令。

理解这个过程，可以解释很多常见现象：为什么带空格的路径需要引号，为什么 `$HOME` 会变成一个目录，为什么 `*.md` 会变成多个文件名。本课只讲这些最常用的规则，不展开重定向、管道和完整的 Shell 脚本语法。

## 核心内容

### 空格通常用来分隔参数

在没有引号的情况下，空格通常表示一个参数结束：

~~~bash
printf '<%s>\n' hello world
~~~

`printf` 会收到两个参数，因此输出两行：

~~~text
<hello>
<world>
~~~

如果希望带空格的内容作为一个整体，需要使用引号：

~~~bash
printf '<%s>\n' 'hello world'
~~~

这次 `printf` 只收到一个参数，输出一行：

~~~text
<hello world>
~~~

### 单引号和双引号

单引号会尽量保留其中的原始字符：

~~~bash
name=Shell
printf '<%s>\n' '$name'
~~~

输出是：

~~~text
$name
~~~

双引号会保留空格，但允许变量和命令替换继续生效：

~~~bash
printf '<%s>\n' "$name"
printf '<%s>\n' "$name basics"
~~~

输出是：

~~~text
<Shell>
<Shell basics>
~~~

可以先记住：

- 单引号适合表示完全不需要展开的原始文本。
- 双引号适合包住可能包含空格的变量或命令结果。
- 引号是 Shell 的语法，通常不会作为字符传给最终命令。

### 反斜杠可以取消特殊含义

反斜杠 `\` 通常会让紧跟其后的字符失去特殊含义：

~~~bash
printf '<%s>\n' hello\ world
printf '<%s>\n' \$name
~~~

第一条命令中的 `\ ` 不再表示参数分隔，所以 `hello world` 是一个参数；第二条命令中的 `\$` 会保留字面量 `$`，不会展开变量。

在实际书写中，表示一段完整文本时通常优先使用引号，反斜杠更适合处理单个特殊字符。

### 变量展开

Shell 可以先保存一个值，再在命令中使用它：

~~~bash
name=Shell
printf '主题：%s\n' "$name"
~~~

`$name` 会在命令执行前被替换为 `Shell`。这里的 `name=Shell` 是给当前 Shell 设置一个变量，不要在等号两边加空格。

变量作为文本或路径使用时，通常应该写成 `"$name"`。双引号可以避免变量值中的空格被意外拆成多个参数。

### 命令替换

`$(...)` 可以先执行括号中的命令，再把命令输出放入当前命令：

~~~bash
printf '当前目录：%s\n' "$(pwd)"
~~~

执行过程可以理解为：

1. Shell 先执行 `pwd`。
2. `pwd` 输出当前目录。
3. Shell 把这个目录文本作为一个参数交给 `printf`。

命令替换适合把一个命令的结果传给另一个命令。括号中的命令仍然由 Shell 执行，`printf` 只负责显示最终得到的文本。

### 通配符展开

Shell 会把部分通配符展开成匹配的文件名：

~~~bash
printf '<%s>\n' ./*.md
~~~

其中：

- `*` 匹配任意长度的字符，但通常不跨越目录分隔符 `/`。
- `?` 匹配一个字符。
- `[...]` 匹配方括号中的某一个字符。

如果当前目录有 `README.md` 和 `notes.md`，Shell 可能会把：

~~~text
./*.md
~~~

展开成：

~~~text
./README.md ./notes.md
~~~

然后 `printf` 实际收到的是两个文件名，而不是字符串 `./*.md`。

通配符不是正则表达式，主要用于匹配文件名。不同 Shell 在“没有匹配到文件”时的处理可能不同；Zsh 通常会直接提示 `no matches found`，Bash 默认可能保留原样的 `*.md`。

### Shell 最终交给命令什么

可以用下面的简化模型理解一行命令：

~~~text
原始文本
    ↓
根据空格、引号和转义符区分参数
    ↓
展开变量和命令替换
    ↓
展开匹配到的文件名通配符
    ↓
把处理后的参数交给命令
~~~

不同 Shell 在细节上可能有差异，但这个模型足够解释大多数基础命令行行为。遇到路径包含空格、变量值不符合预期或通配符报错时，优先检查引号和展开规则。

## 示例：观察不同写法最终产生的参数

~~~bash
name=Shell
printf '<%s>\n' "$name" "$name basics" 'literal: $name' "$(pwd)"
~~~

这条命令使用了四种情况：

- `"$name"`：展开变量，得到 `Shell`。
- `"$name basics"`：展开变量，同时保留整个参数中的空格。
- `'literal: $name'`：单引号阻止变量展开。
- `"$(pwd)"`：先执行 `pwd`，再把结果作为一个参数传入。

注意，`printf` 最终看到的是展开后的参数，原来的引号和 `$` 处理符号不会出现在输出中。

## 小结（掌握范围）

本课必须掌握：

- 知道空格通常会把一行命令分成多个参数。
- 会用单引号、双引号和反斜杠控制参数边界及特殊字符的含义。
- 能看懂基本的变量展开，如 `$name`。
- 能看懂基本的命令替换，如 `$(pwd)`。
- 知道 `*`、`?` 和 `[...]` 可以展开为匹配的文件名。
- 变量作为文本或路径使用时，养成使用双引号包住变量的习惯。
- 理解 Shell 会先处理命令文本，再把最终参数交给命令。

## 课后小实操

### 实操一

观察引号、变量和命令替换对最终参数的影响。使用 `printf` 两端的尖括号，可以清楚看到每个参数的边界。

**操作步骤**

~~~bash
name=Shell
printf '<%s>\n' $name "$name basics" '$name basics' "$(pwd)"
~~~

**运行结果**

~~~text
❯ printf '<%s>\n' $name "$name basics" '$name basics' "$(pwd)"
<Shell>
<Shell basics>
<$name basics>
</home/ubzy/AI-Infra-Knowledge-Base>
~~~

**概括**
1. 直接替换
2. 双引号在字符串中替换 
3. 单引号纯字符串，没有替换语义 
4. 先执行pwd，再替换为结果

### 实操二

观察通配符如何匹配当前目录中的 Markdown 文件。这个操作适合快速把一组同类型文件交给后续命令处理；本次只显示文件名，不会修改文件。

**操作步骤**

~~~bash
printf '当前目录：%s\n' "$(pwd)"
printf '当前目录下的 Markdown 文件：\n'
printf '<%s>\n' ./*.md
~~~

请在仓库根目录或本主题目录执行。如果当前目录没有 Markdown 文件，Zsh 提示 `no matches found` 是通配符没有匹配到文件的表现。

**运行结果**

~~~text
❯ printf '当前目录：%s\n' "$(pwd)"
当前目录：/home/ubzy/AI-Infra-Knowledge-Base
❯ printf '当前目录下的 Markdown 文件：\n'
当前目录下的 Markdown 文件：
❯ printf '<%s>\n' ./*.md
<./AGENTS.md>
<./AI Infra 云端学习路线（NVIDIA + 昇腾双栈）.md>
<./README.md>
~~~

**概括**
`$(pwd)`先执行pwd然后再替换为字符串，`*.md` 是通配符
