# 前台后台、作业控制与信号

## 引入

有些命令会运行很久。如果一直让它占据终端，就无法继续输入其他命令；如果误操作，又需要能够暂停、恢复或结束它。

Shell 的作业控制解决了这个问题：前台决定谁正在使用终端，后台允许任务继续运行，信号则用来通知任务暂停、继续或退出。本课使用安全的 `sleep` 命令模拟长任务，不会修改文件。

## 核心内容

### 前台任务

直接输入命令时，它默认在前台运行：

~~~bash
sleep 60
~~~

`sleep 60` 表示等待 60 秒后结束，本身通常没有输出。等待期间，Shell 不会显示新的提示符，因为当前终端的前台任务是 `sleep`。

前台任务通常可以读取键盘输入，也会接收 `Ctrl-C`、`Ctrl-Z` 等终端控制按键产生的信号。

### 后台任务

在命令末尾加 `&`，可以让它在后台运行：

~~~bash
sleep 60 &
~~~

Shell 通常会立即返回提示符，并显示类似：

~~~text
[1] 12345
~~~

其中：

- `[1]` 是当前 Shell 分配的作业号。
- `12345` 是进程号 PID，实际数字每次都可能不同。

后台运行只表示 Shell 不等待它结束，并不表示它已经脱离当前终端或登录会话。

### 作业与进程的区别

进程是操作系统正在管理的程序实例；作业是当前 Shell 用来管理一条命令或一组管道进程的单位。

一条简单命令通常对应一个作业和一个进程，但管道可能包含多个进程：

~~~bash
printf 'a\nb\n' | wc -l
~~~

这条管道在 Shell 看来是一个作业，内部则可能有 `printf` 和 `wc` 两个进程。

作业号只在创建它的当前 Shell 中有效。新开一个终端后，不能用原来 Shell 的作业号继续管理它。

### 用 `jobs` 查看当前作业

`jobs` 会显示当前 Shell 管理的后台或暂停作业：

~~~bash
jobs
~~~

常见状态包括：

- `Running`：正在运行。
- `Stopped`：已经暂停。
- `Done`：已经结束。

`jobs -l` 会额外显示进程号：

~~~bash
jobs -l
~~~

`jobs` 只查看当前 Shell 的作业，不是系统中全部进程的列表。

### `Ctrl-C`：请求前台任务中断

在前台任务运行时按 `Ctrl-C`，终端通常会向前台任务发送 `SIGINT` 信号。

多数命令收到 `SIGINT` 后会结束并把控制权交还给 Shell，但程序也可以自行处理或忽略这个信号。因此，`Ctrl-C` 的含义更准确地说是“请求中断”，而不是保证强制结束。

### `Ctrl-Z`：暂停前台任务

在前台任务运行时按 `Ctrl-Z`，终端通常会发送 `SIGTSTP` 信号，使任务暂停：

~~~bash
sleep 120
~~~

按下 `Ctrl-Z` 后，Shell 可能显示：

~~~text
[1]+  Stopped    sleep 120
~~~

暂停不等于结束。任务仍然存在，只是暂时不继续执行，可以通过 `fg` 或 `bg` 恢复。

### 用 `fg` 和 `bg` 恢复任务

`fg` 把暂停或后台任务放回前台：

~~~bash
fg %1
~~~

`bg` 让暂停任务在后台继续运行：

~~~bash
bg %1
~~~

`%1` 表示作业号 1。实际使用时，应先通过 `jobs` 查看编号；如果显示的是 `[2]`，就使用 `%2`。

不指定作业号时，`fg` 和 `bg` 通常操作当前作业，但初学阶段明确写出作业号更容易确认目标。

### 用 `kill` 发送信号

`kill` 的本质是向进程或作业发送信号，不一定是立即强制结束。

下面的命令向作业 1 发送默认的 `SIGTERM`：

~~~bash
kill %1
~~~

也可以明确写出信号名称：

~~~bash
kill -TERM %1
~~~

`SIGTERM` 表示请求程序正常退出，程序有机会保存状态和释放资源。也可以使用进程号：

~~~bash
kill -TERM 12345
~~~

`SIGKILL` 会由内核直接结束进程，程序无法处理或清理资源：

~~~bash
kill -KILL 12345
~~~

不要把 `SIGKILL` 当作日常首选。通常先尝试 `Ctrl-C` 或 `SIGTERM`，只有程序无法正常退出时才考虑强制结束。

### 常见信号

| 信号 | 常见来源 | 常见作用 |
| --- | --- | --- |
| `SIGINT` | `Ctrl-C` | 请求中断前台任务 |
| `SIGTSTP` | `Ctrl-Z` | 暂停前台任务 |
| `SIGCONT` | `fg`、`bg` | 让暂停任务继续 |
| `SIGTERM` | `kill` 默认信号 | 请求程序正常退出 |
| `SIGKILL` | `kill -KILL` | 强制结束，无法被程序处理 |
| `SIGHUP` | 终端或会话关闭 | 通知会话相关进程终端已断开 |

### 后台运行不等于脱离终端

`command &` 只是把命令放到当前 Shell 的后台。任务仍可能和当前终端绑定，关闭终端或断开 SSH 后可能收到 `SIGHUP` 并退出。

需要长期运行的服务，应交给服务管理器、任务系统或终端复用工具管理。后台作业适合当前交互会话中的临时任务，不应直接代替正式的服务运行方式。

## 示例：暂停、恢复并结束一个任务

先启动一个前台任务：

~~~bash
sleep 120
~~~

按 `Ctrl-Z` 暂停它，然后查看作业：

~~~bash
jobs
~~~

假设作业号是 1，让它在后台继续：

~~~bash
bg %1
jobs
~~~

再把它放回前台：

~~~bash
fg %1
~~~

最后按 `Ctrl-C` 请求结束。整个过程没有修改文件，只是在当前 Shell 中改变同一个作业的状态。

## 小结（掌握范围）

本课必须掌握：

- 能区分前台任务和后台任务。
- 会使用 `&` 启动后台任务。
- 能区分 Shell 作业号和操作系统进程号 PID。
- 会使用 `jobs` 和 `jobs -l` 查看当前 Shell 的作业。
- 知道 `Ctrl-C` 通常发送 `SIGINT`，用于请求中断前台任务。
- 知道 `Ctrl-Z` 通常发送 `SIGTSTP`，用于暂停前台任务。
- 会使用 `fg %作业号` 和 `bg %作业号` 恢复任务。
- 会使用 `kill %作业号` 请求任务退出，知道默认信号是 `SIGTERM`。
- 知道 `SIGKILL` 无法被程序处理，只应作为最后手段。
- 理解后台任务仍属于当前会话，关闭终端后不保证继续运行。

## 课后小实操

### 实操一

启动一个后台任务，查看作业号和 PID，再把它切换到前台并用 `Ctrl-C` 结束。

**操作步骤**

~~~bash
sleep 120 &
jobs -l
~~~

记下 `jobs -l` 显示的实际作业号。下面以作业号 1 为例；如果你的编号不同，请替换 `%1`：

~~~bash
fg %1
~~~

任务进入前台后按 `Ctrl-C`，然后确认当前作业列表：

~~~bash
jobs
~~~

**运行结果**

~~~text
❯ sleep 120 &
[1] 19744
❯ jobs -l
[1]  + 19744 running    sleep 120
❯ jobs
[1]  + running    sleep 120
❯ fg %1
[1]  + 19744 running    sleep 120
^C
❯ jobs
~~~

**概括**
1. & 让任务在后台执行 保持running
2. 作业号代表当前任务，可能包含多个PID
3. fg 意思是前台，ctrl-c 发送 SIGINT 信号请求中断任务

### 实操二

启动一个前台任务，暂停后在后台恢复，最后使用 `kill` 请求它正常退出。

**操作步骤**

先运行：

~~~bash
sleep 120
~~~

按 `Ctrl-Z` 暂停任务，然后执行：

~~~bash
jobs
bg %1
jobs
kill %1
jobs
~~~

上面的命令以作业号 1 为例，请使用 `jobs` 显示的实际编号。`kill` 后 Shell 可能立即或在下一次提示符出现时报告任务已经结束。

**运行结果**

~~~text
❯ sleep 120
^Z
[1]  + 31304 suspended  sleep 120
❯ jobs
[1]  + suspended  sleep 120
❯ bg %1
[1]  + 31304 continued  sleep 120
❯ jobs
[1]  + running    sleep 120
❯ kill %1
[1]  + 31304 terminated  sleep 120                                                                  
❯ jobs

~~~

**概括**
1. Ctrl-Z 暂停执行并挂到后台
2. bg %1 恢复执行但是依然挂在后台
3. kill %1 停止执行
