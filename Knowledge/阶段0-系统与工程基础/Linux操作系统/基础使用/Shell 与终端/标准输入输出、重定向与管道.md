# 标准输入输出、重定向与管道

## 引入

命令的输出默认显示在终端上，但实际工作中我们经常需要把输出保存成日志、把文件内容交给命令处理，或者把多个简单命令串成一条处理链。

这背后依靠的是 Shell 的标准输入、标准输出、标准错误、重定向和管道。本课先建立这几个概念，再用简单命令完成“保存、读取、组合处理”的过程。

## 核心内容

### 三个标准流

大多数命令启动时都会拥有三个标准数据流：

| 名称 | 文件描述符 | 默认来源或去向 |
| --- | --- | --- |
| 标准输入 stdin | 0 | 键盘 |
| 标准输出 stdout | 1 | 终端 |
| 标准错误 stderr | 2 | 终端 |

可以把它们理解成程序的三个通道：

~~~text
键盘 ──标准输入──> 命令 ──标准输出──> 终端
                         └─标准错误──> 终端
~~~

标准输出和标准错误默认都显示在终端上，但它们是两条不同的通道。正常结果是一条通道，错误信息是另一条通道。

### 用 `>` 保存标准输出

`>` 会把命令的标准输出写入文件：

~~~bash
printf '第一行\n' > report.txt
~~~

如果 `report.txt` 不存在，Shell 会创建它；如果已经存在，`>` 会先清空原内容，再写入新的输出。

因此，使用 `>` 前一定要确认目标文件。对重要文件操作时，不要因为习惯而直接覆盖。

### 用 `>>` 追加标准输出

`>>` 也会把标准输出写入文件，但不会清空原内容，而是追加到文件末尾：

~~~bash
printf '第二行\n' >> report.txt
~~~

`>` 适合生成一份新的结果，`>>` 适合持续追加日志或记录。

### 用 `wc` 统计文本

`wc` 用来统计文本的行数、单词数和字节数。常用选项包括：

- `wc -l`：统计行数。
- `wc -w`：统计单词数。
- `wc -c`：统计字节数。

例如：

```bash
printf '第一行\n第二行\n' | wc -l
```

结果是 `2`，表示输入内容有两行。本课主要使用 `wc -l`，把它和重定向或管道结合起来统计文件或命令输出的行数。

### 用 `<` 提供标准输入

`<` 会把文件内容作为命令的标准输入：

~~~bash
wc -l < report.txt
~~~

这里 `wc -l` 不需要从键盘读取，而是从 `report.txt` 读取内容并统计行数。命令本身并不知道输入来自文件，Shell 在启动命令前完成了连接。

本课实操中的 `cat` 是一个常用的内容查看命令，`cat report.txt` 会把文件内容写到标准输出，也就是默认显示在终端上。

### 重定向标准错误

因为标准错误的文件描述符是 2，所以可以用 `2>` 单独保存错误信息：

~~~bash
ls /path/that-does-not-exist > normal.log 2> error.log
~~~

这条命令中：

- 正常输出写入 `normal.log`。
- 错误信息写入 `error.log`。
- 两类信息不会混在一起。

只写 `> normal.log` 时，默认只重定向标准输出，错误信息仍然会显示在终端。

如果确实希望把标准输出和标准错误合并到同一个文件，可以使用：

~~~bash
some-command > all.log 2>&1
~~~

`2>&1` 表示让标准错误跟随标准输出当前指向的位置。这个写法先记住即可，不必在本课深入文件描述符的实现细节。

### 用 `|` 连接两个命令

管道符 `|` 会把左侧命令的标准输出，连接到右侧命令的标准输入：

~~~bash
printf 'api\nworker\napi\n' | wc -l
~~~

执行过程是：

1. `printf` 产生三行文本。
2. 管道把这三行文本交给 `wc -l`。
3. `wc -l` 统计收到的行数并输出 `3`。

管道连接的是数据流，不是文件。它可以让每个命令只负责一件事，再把多个命令组合起来完成更复杂的处理。

例如：

~~~bash
printf 'banana\napple\ncherry\n' | sort
~~~

`printf` 产生文本，`sort` 接收这些文本并排序。只有管道最右侧命令的标准输出默认显示在终端。

注意，管道默认只连接标准输出；左侧命令的错误信息不会自动进入右侧命令。

### 用 `tee` 一边显示一边保存

`tee` 会读取标准输入，同时把内容写到终端和文件：

~~~bash
printf 'api\nworker\n' | tee services.txt
~~~

这条命令既会在终端显示两行内容，也会把内容保存到 `services.txt`。

如果希望追加而不是覆盖文件，可以使用：

~~~bash
printf 'database\n' | tee -a services.txt
~~~

`tee` 在查看日志、保存中间结果和排查管道问题时很有用。

## 示例：保存结果并继续处理

下面的命令先生成一份服务清单，同时保存它，再统计文件中的记录数：

~~~bash
printf 'api\nworker\napi\n' | tee /tmp/services.txt
wc -l < /tmp/services.txt
~~~

第一条命令把内容显示出来并写入文件，第二条命令通过 `<` 读取文件并统计行数。这里没有修改仓库中的文件，`/tmp/services.txt` 只是临时练习文件。

## 小结（掌握范围）

本课必须掌握：

- 知道标准输入、标准输出和标准错误分别对应 0、1、2。
- 知道命令默认从键盘读取输入，并把正常输出和错误输出显示到终端。
- 会使用 `>` 覆盖写入，使用 `>>` 追加写入。
- 能看懂 `wc -l`，知道它用于统计文本行数。
- 会使用 `<` 把文件内容交给命令处理。
- 会使用 `2>` 单独保存错误信息，知道 `>` 默认不会捕获错误。
- 能看懂 `2>&1` 合并标准输出和标准错误的常用写法。
- 会使用 `|` 把一个命令的标准输出交给另一个命令。
- 会使用 `tee` 同时显示并保存管道中的内容。
- 使用 `>` 或 `tee` 前会确认目标文件，避免意外覆盖重要内容。

## 课后小实操

### 实操一

练习覆盖写入、追加写入和输入重定向，完成一份简单的文本记录并统计行数。练习文件位于 `/tmp`，不会修改仓库内容。

**操作步骤**

~~~bash
printf '第一行记录\n' > /tmp/shell-io-practice.txt
printf '第二行记录\n' >> /tmp/shell-io-practice.txt
cat /tmp/shell-io-practice.txt
wc -l < /tmp/shell-io-practice.txt
~~~

这里的 `>` 会重建练习文件，`>>` 会追加第二行；如果该文件已存在，确认它是本课练习文件后再执行。

**运行结果**

~~~text
❯ printf '第一行记录\n' > /tmp/shell-io-practice.txt
❯ printf '第二行记录\n' >> /tmp/shell-io-practice.txt
❯ cat /tmp/shell-io-practice.txt
第一行记录
第二行记录
❯ wc -l < /tmp/shell-io-practice.txt
2
~~~

**概括**
1. 覆写or创建后再覆写
2. 追加
3. 输出
4. < 把文件内容作为输入，给 `wc` 命令

### 实操二

练习使用管道和 `tee`，在查看服务清单的同时保存它，并统计保存后的记录数。

**操作步骤**

~~~bash
printf 'api\nworker\napi\n' | tee /tmp/shell-pipe-practice.txt
printf '记录条数：\n'
wc -l < /tmp/shell-pipe-practice.txt
~~~

**运行结果**

~~~text
❯ printf 'api\nworker\napi\n' | tee /tmp/shell-pipe-practice.txt
api
worker
api
❯ printf '记录条数:\n'
记录条数:
❯ wc -l < /tmp/shell-pipe-practice.txt
3
~~~

**概括**

| 把 printf 的输出通过管道“流向” tee, tee 同时写入 /tmp/shell-pipe-practice.txt 并且打印在终端
