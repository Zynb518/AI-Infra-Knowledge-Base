# 软件包查询与安装状态

## 引入

上一课比较 `apt show` 和 `dpkg-query` 时，`coreutils` 的仓库版本是 `9.4-3ubuntu6.3`，本机已安装版本是 `9.4-3ubuntu6.2`。版本不同并不矛盾：一个版本来自 APT 的软件包索引，另一个来自本机的 dpkg 安装记录。

本课学习如何查看已安装版本、APT 候选版本以及候选版本来自哪个软件源。所有查询都是只读操作，不会安装或更新软件。

## 核心内容

### 用 apt-cache policy 查看候选版本

`apt-cache policy` 可以显示某个包的本机已安装版本、APT 当前候选版本，以及索引中可见的版本来源：

```bash
apt-cache policy coreutils
```

重点看三个部分：

- `Installed`：dpkg 数据库记录的本机版本；未安装时通常显示 `(none)`。
- `Candidate`：根据本机 APT 索引和软件源策略，APT 当前会优先选择的版本。
- `Version table`：APT 当前索引里可见的版本及其来源。

候选版本根据本机已保存的索引计算。若索引较旧，它未必反映远端仓库此刻最新的版本；此查询本身不会刷新索引。[apt-cache(8)](https://manpages.debian.org/bookworm/apt/apt-cache.8.en.html)

### 用 dpkg-query 查看本机安装状态

`dpkg-query -W` 简洁地显示包名和本机登记的版本；`dpkg-query -s` 则显示更完整的安装状态记录：

```bash
dpkg-query -s coreutils
```

在输出中查看 `Status` 和 `Version`。已完成安装的常见状态是 `install ok installed`。这条记录来自本机 dpkg 数据库，不会查询软件源。[dpkg-query(1)](https://manpages.debian.org/bookworm/dpkg/dpkg-query.1.en.html)

### 比较结果时要分清三种状态

- `Installed` 表示当前实际登记在本机的版本。
- `Candidate` 表示按照当前本机索引和策略，APT 会选择的版本。
- 软件源的版本记录表示索引中有哪些版本可供 APT 考虑。

如果 `Candidate` 高于 `Installed`，表示本机索引显示有较新的候选版本；这不表示该版本已经安装。候选版本也不一定永远是版本号最大的那个，APT 还会考虑软件源优先级等策略。

## 示例

查询 `coreutils` 的候选版本：

```bash
apt-cache policy coreutils
```

根据上一课的查询结果，示意输出可能如下；实际优先级、来源和候选版本以本机输出为准：

```text
coreutils:
  Installed: 9.4-3ubuntu6.2
  Candidate: 9.4-3ubuntu6.3
  Version table:
     9.4-3ubuntu6.3 500
        <软件源地址> noble-updates/main amd64 Packages
 *** 9.4-3ubuntu6.2 100
        /var/lib/dpkg/status
```

这里 `.2` 是本机已安装版本，`.3` 是 APT 选择的候选版本；版本表说明 APT 从哪里得知这些记录。查看候选版本不会安装它。

## 小结（掌握范围）

本课必须掌握：

- 会用 `apt-cache policy` 查看已安装版本、候选版本和版本来源。
- 会用 `dpkg-query -s` 查看本机包状态和安装版本。
- 能解释 `Installed`、`Candidate` 和版本表分别表示什么。
- 知道候选版本来自本机保存的索引，查询不会安装或更新软件。
- 不会把“仓库有较新版本”误认为“较新版本已经安装”。
