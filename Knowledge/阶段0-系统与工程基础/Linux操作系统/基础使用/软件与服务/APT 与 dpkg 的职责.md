# APT 与 dpkg 的职责

## 引入

上一课用 `apt show` 查看了 `coreutils` 的软件包信息。接下来要分清两个经常一起出现的工具：APT 主要处理软件仓库、依赖和操作计划；`dpkg` 主要记录并管理本机 Debian 软件包的安装状态。

知道它们各自负责什么，可以帮助我们选择合适的查询方式，也能理解为什么日常从软件仓库安装软件通常使用 APT。

## 核心内容

### APT 面向软件仓库并处理依赖

APT 使用本机的软件包索引查找仓库中的包，计算依赖关系，并规划下载、安装、升级或移除哪些包。安装或移除时，APT 会把具体的软件包操作交给底层工具完成。

因此，`apt show` 主要回答“当前软件包索引里，这个包是什么、有哪些依赖、有哪些版本信息”。它显示的仓库信息不等同于本机已经安装的状态。

### dpkg 管理本机软件包数据库

`dpkg` 直接处理 Debian 格式的 `.deb` 软件包，也维护本机已安装包的状态信息。查询已安装版本可以使用 `dpkg-query -W`：

```bash
dpkg-query -W bash
```

如果 Bash 已安装，输出通常包含包名和本机登记的版本。该查询读取本机 dpkg 数据库，不会访问仓库，也不会安装或修改软件。

`dpkg` 不会像 APT 一样从仓库下载缺失的依赖并为你规划完整安装方案。直接处理一个 `.deb` 包时，如果依赖没有满足，可能会留下尚未配置完成的软件包；遇到这种情况应先检查状态和依赖，不要随意使用强制选项。

### 两者如何配合

可以用一个简单模型记住职责：

```text
APT：查询仓库、解析依赖、规划并下载软件包
                         ↓
dpkg：解包、配置并记录本机软件包状态
```

大多数从仓库安装、升级或移除软件的日常操作由 APT 发起；APT 再让 dpkg 完成本机的软件包操作。两者都会围绕本机已安装包的信息工作，但 APT 还额外管理仓库索引和依赖规划。

APT 是面向用户的高层包管理接口；`dpkg` 是较底层的 Debian 包管理工具。[apt(8)](https://manpages.debian.org/testing/apt/apt.8.en.html) [dpkg(1)](https://manpages.debian.org/bookworm/dpkg/dpkg.1.en.html)

## 示例

下面分别查看 Bash 的仓库信息和本机安装记录：

```bash
apt show bash
dpkg-query -W bash
```

`apt show` 中的版本来自 APT 当前掌握的软件包信息；`dpkg-query -W` 显示本机登记的已安装版本。两者可能相同，也可能不同，例如仓库已经提供更新版本而本机尚未升级。

## 小结（掌握范围）

本课必须掌握：

- 知道 APT 面向仓库，负责查找包、解析依赖和规划包操作。
- 知道 dpkg 直接管理本机 Debian 软件包及其安装状态。
- 会用 `dpkg-query -W` 查询本机已安装包的版本。
- 能区分 APT 仓库信息与 dpkg 本机安装记录。
- 知道 dpkg 不会像 APT 一样自动从仓库获取缺失依赖并规划完整操作。
