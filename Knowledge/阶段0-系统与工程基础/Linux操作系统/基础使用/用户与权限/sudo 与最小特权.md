# sudo 与最小特权

## 引入

有些系统操作需要管理员权限，但日常工作不应一直以管理员身份进行。`sudo` 可以在授权范围内临时提升一条命令的权限；理解它的边界，能减少误改系统文件或扩大权限带来的风险。

本课学习如何观察当前身份、了解 `sudo` 授权范围，以及什么时候应使用最小权限完成任务。

## 核心内容

### 管理员身份与当前身份

Linux 中 `root` 的 UID 通常是 `0`。可以用 `id -u` 查看当前命令的 UID，用 `whoami` 查看当前用户名。

普通用户加入 `sudo` 组通常表示可以申请某些管理员操作，但最终能运行哪些命令由系统的 sudo 策略决定。使用 `sudo -l` 可以查看当前用户被允许执行的命令；部分系统会要求先输入自己的密码进行验证。

### sudo 提升的是命令，不是整个终端

常见形式是 `sudo 命令 参数`。如果当前策略允许，`sudo` 会以授权的目标身份运行这条命令；默认目标通常是 `root`。命令结束后，交互式 Shell 仍回到原来的用户身份。

可以用 `sudo id -u` 观察单条命令是否以 UID `0` 运行，再用 `whoami` 确认当前 Shell 仍是原来的用户。`sudo` 可能要求输入密码，但不会把当前终端永久切换成 `root`。

### 最小特权原则

最小特权的意思是：只在确实需要时，为确实需要的那条命令使用足够的权限。

- 如果普通用户能完成任务，就不加 `sudo`。
- 使用 `sudo` 前，先确认命令、参数和目标路径。
- 优先用只读查询定位问题，不用扩大文件权限来绕过问题。
- 不把整段不熟悉的命令链或脚本交给管理员权限运行。
- 如果 `sudo -l` 显示没有授权，按正常授权流程联系系统管理员，不尝试绕过限制。

权限问题通常应先检查当前身份、文件所有者、所属组和权限位。只有操作本身确实需要管理员权限，且当前用户得到授权时，才使用 `sudo`。

## 示例

对比普通身份和提权命令的 UID，并检查命令结束后当前 Shell 的身份：

```bash
id -u
sudo id -u
whoami
```

假设普通用户 UID 是 `1000`，输出可能类似：

```text
1000
0
ubzy
```

第二行显示提权查询以 UID `0` 运行；最后一行仍显示普通用户，说明单条命令结束后，当前 Shell 没有永久切换身份。

## 小结（掌握范围）

本课必须掌握：

- 知道 `root` 通常使用 UID `0`，会区分当前用户与提权命令的运行身份。
- 知道 `sudo` 只为单条命令申请授权，不会永久切换当前 Shell 身份。
- 会用 `sudo -l` 查看当前用户的授权范围。
- 知道是否属于 `sudo` 组和实际可运行的命令还受系统策略控制。
- 能在权限排查时遵循最小特权：先用普通身份和只读查询，只在必要且获授权时使用 `sudo`。

## 课后小实操

### 实操一

查看当前账号可使用的 sudo 授权范围，练习区分“属于某个组”和“具体允许执行什么”。

**操作步骤**

先回顾上一课记录的当前用户和所属组，再使用本课介绍的授权查询查看当前账号允许执行的命令范围。记录查询是否要求密码、允许的目标身份与命令范围，并说明这些信息能否仅凭当前组名推断出来。

本实操只查询授权信息，不执行列表中的管理命令，不修改文件、权限或系统配置。若系统明确拒绝查询或当前账号没有授权，记录该结果即可，不尝试绕过。

先把查询命令写入代码区，再执行并记录真实输出；不要在代码或结果区粘贴密码。
