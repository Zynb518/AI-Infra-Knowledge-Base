# 异常流程与抛出

## 引入

捕获异常只解决了“出错时怎么办”。编写脚本时，还需要区分成功后才做的事、无论结果如何都要做的收尾工作，以及主动拒绝不合要求的数据。本课把这些执行路径串起来。

## 核心内容

### `else`：仅在 `try` 成功后执行

`else` 写在所有 `except` 之后。当 `try` 正常执行完且没有异常时，才会执行 `else`：

```python
raw = "8"

try:
    count = int(raw)
except ValueError:
    print("数量不是整数")
else:
    print(f"数量：{count}")
```

如果把 `raw` 改成 `"8x"`，就会执行 `except`，跳过 `else`。把成功后的操作放在 `else` 中，也能避免把这些操作自身的错误误认为是 `try` 中转换数据的错误。

### `finally`：离开 `try` 语句前执行

`finally` 放在最后。`try` 成功或被 `except` 处理后，它都会执行；即使异常没有被当前代码捕获，在继续向外传递前也会执行 `finally`。因此它适合做收尾工作：

```python
raw = "8x"

try:
    int(raw)
except ValueError:
    print("转换失败")
finally:
    print("检查结束")
```

这段代码会先输出“转换失败”，再输出“检查结束”。

### `raise`：主动抛出异常

当数据虽然能完成基本转换，却不符合业务要求时，可以用 `raise` 主动报告错误：

```python
def parse_positive_count(text):
    count = int(text)
    if count <= 0:
        raise ValueError("数量必须大于 0")
    return count
```

`int(text)` 可能自己抛出 `ValueError`；当结果小于或等于 `0` 时，函数会主动抛出一个带说明的 `ValueError`。在 `except` 中单独写 `raise`，则会重新抛出当前正在处理的异常。

### 异常会传给调用处

函数内部发生异常且没有在函数内处理时，调用处可以捕获它。如果调用处也没有处理，异常会继续向外传递，最终显示错误信息并结束当前执行流程。

## 示例

下面的函数检查端口号是否为 `1` 到 `65535` 之间的整数，调用处负责处理配置错误：

```python
def parse_port(text):
    port = int(text)
    if port < 1 or port > 65535:
        raise ValueError("端口号必须在 1 到 65535 之间")
    return port

raw_port = "70000"

try:
    port = parse_port(raw_port)
except ValueError as error:
    print(f"配置错误：{error}")
else:
    print(f"使用端口：{port}")
finally:
    print("端口检查结束")
```

`"70000"` 能转成整数，但超出范围，因此函数抛出 `ValueError`；调用处输出错误，跳过 `else`，最后执行 `finally`。把输入改成 `"8080"` 时会走成功分支，随后也会执行 `finally`。

## 小结（掌握范围）

- 能用 `else` 放置只在 `try` 成功时执行的代码。
- 能用 `finally` 表达无论成功或发生异常都要执行的收尾操作。
- 能用 `raise` 主动报告不合要求的数据，并在需要时重新抛出当前异常。
- 能解释函数中的异常如何传到调用处，以及调用处的 `except` 如何处理它。
